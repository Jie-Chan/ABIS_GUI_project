## 服务监控

全量汇总保持全部 10、正常 8、异常 1、未知 1。上方按 ABIS-System、算法服务 1、算法服务 2 显示三张紧凑卡片，下方数据存储表按“组件｜实例｜主机 / IP｜状态”组织四列；依次为三个 PostgreSQL 实例和最后一行 MinIO。两种组件共用行高、字重、边框和状态对齐。

布局按监控内容容器宽度切换，使用容器查询：大于 660px 三列；501–660px 两列，算法服务 2 通栏且内部两项横排；500px 及以下为单列。筛选后只有一张服务卡片时通栏，两张时等宽。1024×900 浏览器首屏可看到三张卡片和全部四行存储表。

筛选不改变全量汇总。异常只显示算法服务 1 的人脸服务，存储区隐藏；未知只显示 MinIO 存储行。刷新保留当前筛选，失败保留上次成功数据和时间，恢复后清除错误提示。主机名称、固定 ID 及 IP 继续与资源页共用。

## 单次请求与历史注册

所有入库变更操作使用该记录的 `requestId` 和 `userId` 跳转。注册和查重的业务关联仍可保存在 Mock 原始请求中，但不再将查重合并到注册变更的跳转结果。抽屉保留当前图像、入库变更两个标签。

U301 14:05 人脸注册仅返回 `RECAP-U301-005`；清除请求 ID，保留用户 U301 查询，可看到 14:06 查重 `RECAP-U301-006`。U302 的两次新注册和三组样例的删除操作也均只返回自身请求。U303 的指纹失败不进入生效变更。

预置入库不再是无日志的独立记录。补齐 13 条成功历史注册，保存实际写入图像、指位与成功时间；当前图像、首次入库时间和变更记录统一重放这些成功请求。每位列表内申请人都至少有一次成功人脸注册。历史时间早于默认样例的查重、删除，原图像和指位继续沿用。

默认未指定对象的日志查询和 CSV 保持原 15 条样例；按完整用户 ID、请求 ID 或兼容的请求 ID 集合查询时包含符合条件的历史注册，其他筛选继续取交集。比如 U006 常规查询可见原查重失败与历史人脸注册两条记录。重置恢复默认展示。

## 请求来源 IP

列表在接收时间后显示原始发起方 `sourceIp`，CSV 同步增加该列。异步示例 `REQ-00000001` 为 `203.0.113.40`，同步 `REQ-00000013` 为 `198.51.100.23`，缺少原始 IP 的 `REQ-00000008` 显示“—”。历史补齐记录未提供原始 IP，也显示“—”。不使用 MQ、适配服务或重试节点 IP 回填。
