## 1. 审阅结论

**目前能确认主要功能已有对应的接口入口，但这份 JSON 尚不足以确认能完整支撑当前 GUI。** 需要补充缺失入口、真实响应、筛选参数与业务规则后，再完成接入和联调验证。

本次以当前页面实际调用为准，同时参考 `src/api/contract.js` 和 mock 实现。仅进行静态对照，未访问服务、登录或执行任何账户、阈值、业务数据写入。因此，下文“文档未列出”不等于“后端未实现”，“Schema 不匹配”也不等于真实服务一定返回错误。

## 4. 页面最低数据需求

以下是**当前页面所消费的前端形状**，可由 HTTP 适配器从真实后端字段转换，不要求后端逐字使用相同字段名。显示文案可由前端常量生成；真实身份、状态、业务值、分页总数不可凭空生成。

| 页面或流程 | 当前前端所需结构 | 特别说明 |
| --- | --- | --- |
| 登录/顶栏/权限 | `token`；`account.id/username/displayName/role` | Token 可从 `data.accessToken` 转换；当前账户信息来源需后端明确。仅根据输入的用户名推测角色不可行。 |
| 账户管理 | `{total, items[]}`；每项 `id/username/displayName/role/enabled/createdAt/lastLoginAt` | 未登录过的时间可约定为 `null`，前端显示 `—`；不要把展示占位符强制要求为服务端值。 |
| 阈值配置 | 读取 `{face, finger}`；保存后获得权威配置 | 两项为数值；上下限与实际生效规则另行确认。 |
| 服务监控 | `{items[], fetchedAt}`；每项 `key/name/layer/status/instances[]`；实例 `id/status` | 对象为 `gateway/system/face/fingerprint/postgresql/minio`；四态为 `normal/abnormal/unreachable/not_deployed`，未部署不计异常。名称、层级可按稳定 key 在前端映射。 |
| 算法指标 | `metrics.cdcHealthy/cdcReady/galleryTotalSize/licenseStatus` | 只在算法对象上展示；前两项布尔、底库规模数值、License 当前取 `VALID/INVALID`。未知状态需明确表示，前端也需适配，不能直接转成失败或正常。 |
| 调用日志 | `{total, items[]}`；每项 `id/calledAt/caller/api/apiLabel/feature/result/costMs` | `api` 为 `comparison/verification/identification/add/delete`；模态 `face/finger`；结果 `success/failure`。`apiLabel` 可在前端生成。 |
| 审计记录 | `{total, items[]}`；每项 `id/operatedAt/operator/role/roleLabel/action/target/beforeValue/afterValue/result/sourceIp/sessionId` | 当前 `result` 为中文 `成功/失败`，不同于调用日志；可以映射。前后值若为对象，可转换展示，但必须明确格式与脱敏规则。`roleLabel` 可在前端生成。 |
| CSV 导出 | 适配器最终提供文件 `Blob` 或调整页面流程 | 当前导出全部筛选结果，CSV 为中文列名、UTF-8 BOM；调用日志 6 列、审计 10 列。若后端返回 Excel 或异步任务，需确认并调整交互。 |

当前日志及审计“详情”都是直接展示列表行数据，没有另发详情请求。**只要列表返回详情所需字段，就不必新增详情接口。** 若后端有意精简列表，才需要另外明确按 ID 查详情的方案。

监控空实例列表目前直接显示“未部署”；如果后端用空列表表达“采集失败/未取得实例”，这处交互也应调整，不能仅靠字段补默认值。
