# Mock 功能预览（2026-11-09）

本版基于当前工作区，包括已有联调界面优化及尚未提交的日志双 ID 查询、申请人列表。以 Mock 功能演示和联动验证为主，延续深蓝顶部导航，不调整业务权限或接口契约。

## 本轮调整

- 页面标题增加对应的功能图标，沿用现有导航、页面名称及设置分组。
- 申请人列表增加人员及入库模态图标；详情突出申请人 ID、人脸和指纹记录数，保留入库时间、更新时间及逐条入库记录。
- 申请人和日志的 ID 查询输入增加搜索图标，日志导出按钮增加下载图标；查询、分页、重置和 CSV 逻辑保持当前实现。

本轮不增加新的业务功能。原有未提交功能继续保留：字符串 ID 精确查询、前导零、组合筛选、查询竞态保护、失败恢复、全部匹配日志导出，以及申请人列表和详情到日志的跳转。

## 启动和演示

在工程根目录执行：

```bash
npm run dev:mock -- --host 127.0.0.1
```

打开 `http://127.0.0.1:5186/login`。管理员：`admin / admin123`；运维员：`ops.zhang / ops123`。数据与写操作仅存在于当前浏览器页面的 Mock 内存，刷新后恢复种子数据。

建议按以下顺序演示：

1. 登录后查看六个监控对象，使用“异常”筛选和“立即刷新”。
2. 打开一级“申请人列表”，默认展示 68 位在库人员，查询 `00000001`。
3. 查看申请人详情，核对人脸和指纹记录，再点击“查看该申请人日志”。
4. 日志页自动带入 `00000001`，查询到 47 条日志；可翻页并导出全部匹配记录。
5. 再输入业务请求 ID `REQ-00000001`，组合查询得到 2 条调用；选择“失败”后剩 1 条。打开详情核对两类 ID。
6. 重置筛选；返回申请人列表查询 `00000068`，查看其日志，演示“在库人员可以没有当前查询范围内的调用记录”。

管理员可管理账户；运维员可查看申请人、日志、审计并配置阈值，不能管理账户。个人信息、改密、阈值确认与离页保护继续保留。
