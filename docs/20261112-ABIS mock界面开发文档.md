# ABIS Mock 界面开发文档

版本日期 2026-11-12

本次更新接续 [[20261111-ABIS mock界面开发文档]]，按界面分章记录日志查询、申请人列表、服务状态监控和审计查询的开发要求及验收项。同一展示项按本文的更新要求实现。

## 1. 日志查询界面

### 1.1 查重图像比对

查重请求在顶部信息表格下方设置「处理过程」「图像比对」两个标签页，默认打开「处理过程」。顶部信息表格在两个标签页中均可见。「处理过程」包含阶段时间线和可展开的 ABIS 接口报文。

「图像比对」左侧展示原始图像，右侧展示选中的候选图像。图像下方分别标注各自的用户 ID。候选排名和接口实际返回的比对分数放在右侧图像上方，可与「候选图像」标题同一行展示。指纹案例在左右图像标题旁分别标注对应指位，例如「左手食指」。两侧图框保持等高并采用紧凑间距，使常见桌面视口首屏能同时看到两张图像、用户 ID、分数及指纹指位。多名候选按本次响应中的顺序切换，切换时保留左侧图像。

本阶段沿用现有图像存储，通过 GUI 后端按用户 ID 查询 ABIS PostgreSQL 中的 MinIO 图像链接，再获取图像供界面展示。左侧用户 ID 取本次请求的待查对象 `userId`，右侧取本次查重响应中对应候选的 `userId`。按请求的生物模态以及已有的部位信息定位对应图像。Mock 使用本地虚构数据模拟该取图过程。

查重明确完成且候选列表为空时，左侧照常展示可获取的原始图像，右侧居中显示「本次查重无候选」。两侧保持一致的背景和间距，右侧采用低对比度的空状态图标和中性文字。尚未取得明确查重结果时，右侧显示「暂无查重结果」。

用户记录或图像链接缺失时，在对应图像位置显示「暂无可用图像」。确认对象已删除时显示「图像已删除或不存在」，临时读取失败时显示「图像加载失败」。保留对应用户 ID 和本次响应记录的候选信息。

图像页顶部显示简短提示「图像根据当前用户记录获取，可能与本次查重时的图像不同；已删除的图像可能无法显示。」

> [!warning] 历史图像一致性
> 此方案按用户 ID 查询当前 ABIS 数据库和 MinIO 中的图像。请求对象或候选对象更新图像后，历史查重记录可能展示更新后的图像。用户记录、图像链接或 MinIO 对象删除后，历史记录中的对应图像可能无法读取。本次查重的候选和分数仍取原响应，图像仅供辅助查看。

「处理过程」页底部按 §1.6 展示可展开的请求参数和响应结果。

### 1.2 请求列表列顺序与接口类型

请求 ID 列放在用户 ID 列前面，依次作为列表第一列和第二列。每条请求都有请求 ID，用户 ID 缺失时显示「—」，该请求仍可通过请求 ID 查询并打开详情。

查重接口的界面名称统一为「1：N查重」。接口类型筛选项显示「1：N查重」，匹配指纹和人脸两种模态。列表和抽屉中保留模态，显示「指纹 1：N查重」或「人脸 1：N查重」。

### 1.3 处理环节名称与展示

将请求列表的「当前阶段」列改名为「处理环节」。列表显示中文名称，Stage 英文代码在抽屉中展开对应阶段后展示。列表与抽屉的阶段标题使用同一套中文名称。

| Stage 代码 | 中文名称 | 含义 |
| --- | --- | --- |
| `ADAPTER_RECEIVED` | 接收请求 | 适配服务接收请求并可靠保存任务。 |
| `ADAPTER_CALLING` | 调用 ABIS | 适配服务发起调用并等待 ABIS 响应。 |
| `ABIS_HANDLING` | ABIS 处理 | ABIS 执行注册、查重、删除等业务。 |
| `ADAPTER_RESPONDED` | 发布结果 | 适配服务保存结果并发布到响应 MQ。 |

「处理环节」沿用既有阶段选择规则。处理中优先显示阻塞任务执行或响应交付的环节，正常完成后显示最后完成的环节。发生异常时显示需要关注的环节，业务失败且失败响应已交付时显示「ABIS 处理」。执行状态和响应发布状态分别说明业务执行结果及响应交付情况。

异步阶段顺序显示为「接收请求 → 调用 ABIS → 发布结果」，「ABIS 处理」位于对应调用尝试内部。同步请求显示「ABIS 处理」。注册、查重、删除由接口类型表达。

### 1.4 多候选查重案例

在原有 13 条请求后追加以下两个异步查重案例，共展示 15 条请求。每个新增案例返回 3 名候选，使用本地虚构图像和响应数据，执行成功且响应已发布。

| 请求 ID | 待查用户 ID | 接口类型 | 按响应顺序返回的候选用户 ID | 业务结果摘要 |
| --- | --- | --- | --- | --- |
| `REQ-00000014` | `U009` | 指纹 1：N查重 | `U101`、`U102`、`U103` | 查重成功 · 候选 3 条 |
| `REQ-00000015` | `U010` | 人脸 1：N查重 | `U201`、`U202`、`U203` | 查重成功 · 候选 3 条 |

两个案例均提供可正常读取的待查对象图像和三名候选图像。指纹案例采用同一指位的原始及候选指纹，沿用已有指位标识；人脸案例提供原始及候选人脸图像。按现有 Mock 接口的分值范围配置三名候选的递减示例分数，候选 ID、排名、分数和图像关联在响应 JSON 与「图像比对」页中保持一致。

进入「图像比对」页时默认选中排名第一的候选，候选列表显示全部三名候选及当前选中项。逐一切换时，右侧图像、用户 ID、排名和分数随之更新，左侧待查图像及其用户 ID 保持可见。两个案例均显示已有的历史图像风险提示。

### 1.5 抽屉信息表格与分区

抽屉标题统一使用「请求详情」。顶部信息表格与下方详情区等宽、左右对齐，中间留约 20 px 间距。表格使用细浅边框和浅色字段背景，保持紧凑行距。

异步请求的信息表格按以下顺序排布。通栏行的字段名占左侧标签格，内容合并右侧三格。

| 行 | 左侧字段与内容 | 右侧字段与内容 |
| --- | --- | --- |
| 1 | 请求 ID，通栏展示 | 合并至左侧内容 |
| 2 | 用户 ID | 接口类型，包含模态及同步／异步标识 |
| 3 | 接收时间，通栏展示完整日期及毫秒 | 合并至左侧内容 |
| 4 | 执行状态 | 响应发布状态 |
| 5 | 请求总耗时；进行中的请求按既有口径显示「已用时」 | ABIS 接口处理耗时 |
| 6 | 业务结果摘要，通栏展示 | 合并至左侧内容 |

同步请求的信息表格省去响应发布状态，耗时仅展示请求总耗时。同步的请求总耗时与 ABIS 接口处理耗时按同一口径计算。字段按剩余空间紧凑排列。移除旧「ABIS 实际处理耗时」及业务处理 Event 中对应的单独用时数值（如 `120 ms`）。业务处理 Event 保留起止时间、结果和异常信息。

下方详情区使用浅色边框包住标签栏和当前页内容。查重请求的「处理过程｜图像比对」标签位于该区域顶部，选中项用主题色文字和下划线突出。标签栏背景与表格字段背景使用同一档浅灰色，内容区以白色为主，内部留约 16 px 边距。通过表格、间距和详情区边框形成上下分区。抽屉标题、表格字段和标签名称承担标题层级。

### 1.6 ABIS 接口报文

将「ABIS 接口响应」区域改为「ABIS 接口报文」，位于处理过程的阶段时间线下方。区域内设置「请求参数」「响应结果」两个可展开项，默认都折叠，点击整行标题即可分别展开或折叠，两项可同时展开。

「请求参数」展示实际发送给 ABIS 接口的请求正文，「响应结果」展示对应的 ABIS 响应正文。JSON 格式化显示，使用浅灰背景，较长内容在代码区域内滚动。报文区域与阶段时间线之间留出间距，使用区域标题和细分隔线组织内容。

有多次 ABIS 调用尝试时，按尝试编号对应各次请求参数与响应结果。缺少已记录正文时，展开后分别显示「暂无请求参数记录」或「暂无响应正文记录」。Mock 为对应调用尝试补充本地虚构的请求参数和响应正文。

### 1.7 阶段默认展开方式

「处理过程」页直接展示阶段标题和时间线，省去额外的「阶段概览」标题。同步请求的单一「ABIS 处理」阶段直接显示接收请求、业务处理、发送响应三个 Event，标题右侧显示状态和耗时，下面显示阶段代码及紧凑起止时间。

异步请求保留三个顶层阶段的折叠操作，首次打开请求详情时按以下规则确定默认展开状态。

| 场景 | 默认展示 |
| --- | --- |
| 异步正常完成 | 三个顶层阶段默认折叠。 |
| 异步处理中、待重试或待人工核查 | 展开当前需要关注的阶段，优先定位阻塞任务执行或响应交付的环节。 |
| 已明确失败，且后续响应交付已完成 | 展开失败所在阶段。失败发生在 ABIS 内部时，同时展开外层「调用 ABIS」和内嵌的「ABIS 处理」。 |
| 历史异常已恢复，最终成功完成 | 按正常完成方式默认折叠，历史异常保留在对应 Event 中。 |

用户手动展开或折叠后，切换「处理过程｜图像比对」时保留其选择。默认展开规则在首次打开该请求详情时应用。

### 1.8 页面标题与紧凑筛选栏

移除页面内容区独立的图标、「日志查询」大标题和「按请求或用户追查处理阶段、事件与响应结果」说明文字。顶部导航通过高亮的「日志查询」标识当前页面，内容区从筛选栏开始。

桌面宽度下，筛选栏按以下顺序紧凑排列为两行，全部筛选条件默认可见。

| 行 | 从左到右的内容 |
| --- | --- |
| 第一行 | 请求 ID、用户 ID、时间范围（开始时间至结束时间）、查询按钮、重置按钮 |
| 第二行 | 接口类型、生物模态、执行状态、总耗时区间（最小值至最大值，单位 ms） |

字段名放在对应输入框或下拉框左侧，与控件垂直居中。请求 ID 排在用户 ID 前面，与列表列顺序一致。按完整 ID 和日期时间的输入需要分配宽度；接口类型、生物模态和执行状态下拉框按选项文本采用紧凑宽度。缩小筛选栏的上下留白和行间距，窄屏时按字段顺序自然换行。

页面从上到下依次为顶部导航、两行紧凑筛选栏、请求数量及导出工具条、日志列表。组合查询和重置沿用现有行为。CSV 按当前筛选结果导出，移除「ABIS 实际处理耗时」列。

### 1.9 验收要求

核对查重请求的两个标签页、公共信息表格、左右图像及各自用户 ID。用 `U001` 的正常查重核对无候选空状态，用 `U002` 的查重核对候选 `U001` 的图像；结合 `U002` 已删除的样例核对左侧图像不可用时的展示。核对图像更新风险提示、图像缺失及加载失败状态，以及多名候选时的切换。

核对列表前两列依次为请求 ID、用户 ID。用户 ID 缺失的记录仍显示请求 ID，并可正常查询和打开详情。

核对列表列名为「处理环节」，列表与抽屉阶段名称均采用本节定义，Stage 英文代码在抽屉展开后可见。正常异步完成记录显示「发布结果 · 成功 · 已发布」；ABIS 明确业务失败且失败响应已交付的记录显示「ABIS 处理 · 失败 · 已发布」。核对响应待发布、待人工核查和同步请求的环节选择仍符合各自的处理进展。

核对新增请求 `REQ-00000014` 和 `REQ-00000015`，列表共 15 条请求。分别打开指纹、人脸案例，核对候选数量为 3、默认选中第一名，并逐一切换三名候选，检查图像模态、指位、用户 ID、排名和分数与响应 JSON 一致。确认左侧待查图像始终可见，顶部业务结果摘要显示「查重成功 · 候选 3 条」。

核对信息表格第一行为请求 ID，接收时间和业务结果摘要通栏展示。异步两个耗时位于同一表格行；同步仅展示请求总耗时，省去响应发布状态。核对上下区域等宽、边缘对齐、间距以及标签栏和详情区的整体边框。

核对「ABIS 接口报文」中的请求参数和响应结果默认均折叠，能够分别及同时展开，JSON 格式化且长内容可滚动。核对多次调用的入参与响应按尝试对应，以及缺少正文时的提示。

用同步样例核对进入详情后直接可见三个 Event。分别核对异步正常完成、处理中、待重试、待人工核查、业务失败及历史异常恢复场景的默认展开状态。ABIS 内部失败时确认内外两层均展开，切换标签页后确认用户手动设置的展开状态得到保留。

核对页面内容区从筛选栏开始，顶部导航高亮「日志查询」。桌面宽度下筛选条件按 §1.8 排列为两行，字段名在控件左侧，请求 ID 位于用户 ID 前面。检查完整 ID 和日期时间输入、下拉选项显示、窄屏换行，以及组合查询、重置和导出功能。

核对筛选、列表与抽屉的查重接口类型均使用「1：N查重」，列表和抽屉能区分指纹与人脸。用两个多候选案例检查首屏的图像、用户 ID、候选分数和指纹指位。切换指纹候选时，右侧指位与对应图像一起更新。核对详情中已移除旧的单独业务处理耗时数值，导出 CSV 后确认表头和数据行均已去掉对应列。

## 2. 申请人列表界面

### 2.1 页面标题与布局

移除内容区独立的图标、「申请人列表」大标题和用途说明。顶部导航高亮「申请人列表」，内容区从筛选栏开始。桌面宽度下，申请人 ID、入库模态、首次入库时间、查询和重置排在同一行。

筛选栏下方显示申请人数量和列表范围说明「仅展示已确认注册成功且当前有效的申请人」，随后展示申请人列表。

### 2.2 验收要求

核对页面首屏从筛选栏开始，桌面端筛选控件保持单行排列。核对申请人数量、列表范围说明、查询和重置功能，以及「查看详情」「查看日志」入口。

## 3. 服务状态监控界面

### 3.1 页面标题与布局

移除内容区独立的图标、「服务状态监控」大标题和用途说明。顶部导航高亮「服务状态监控」，内容区从「全部／正常／异常／未知」状态汇总开始。

汇总下方保留「实例与服务状态」区块标题，在同一行右侧展示状态更新时间和「立即刷新」按钮，下方展示各组实例和服务的状态。

### 3.2 验收要求

核对页面首屏直接显示四类状态数量，状态汇总可以筛选实例和服务。核对区块标题、状态更新时间和「立即刷新」入口的展示及交互。

## 4. 审计查询界面

### 4.1 页面标题与布局

移除内容区独立的图标、「审计查询」大标题和用途说明。顶部导航高亮「审计查询」，内容区从筛选栏开始。桌面宽度下，时间范围、操作人、操作类型、结果、查询和重置排在同一行。

筛选栏下方显示审计记录数量和「导出 CSV」，随后展示审计记录列表。

### 4.2 验收要求

核对页面首屏从筛选栏开始，桌面端筛选控件保持单行排列。核对记录数量、查询、重置、CSV 导出和审计详情入口。
