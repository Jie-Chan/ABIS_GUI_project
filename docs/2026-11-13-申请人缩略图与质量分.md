## 入口与列表

运行 `npm run dev:mock -- --host 0.0.0.0`，访问 `http://服务器IP:5186/login`。登录 `admin / admin123` 或 `ops.zhang / ops123`，从顶部“申请人列表”进入 `/applicants`。

列表依次为“申请人 ID / 人脸 / 指纹 / 首次注册 / 更新时间 / 操作”。人脸缩略图等比完整展示，点击打开该申请人的详情。指纹固定左手五位、右手五位，桌面十指横排、窄屏左右手各排一行。未采集指位保留占位，悬停显示指位及状态；有效记录没有图像或读取失败时显示“图像不可用”。同指位有多条有效记录，列表取图像记录更新时间最新的一条；批量写入时间相同则取该批最后一条。

列表接口一次返回对应的有效图像记录，不额外逐人请求详情。列表查询、分页、首次注册时间范围及两列时间排序继续有效；窄屏表格内部横向滚动，页面本身不横向溢出。

## 两种时间口径

每条 Mock 业务请求明确标记 `collectionRound`：1 为首次采集，2 及以上为后续重采或变更。首次人脸、首次指纹可以分别成功，两者都属于首轮采集。

“首次注册”仍取该 userId 最早一次成功人脸注册。申请人的“更新时间”只取后续轮次成功注册或删除的时间；仅首轮采集时接口返回 null，列表及抽屉均显示“—”。查重、失败注册不推进该值。图像记录自身更新时间仍保存其实际写入时间，并在放大预览中展示。

| 样例及状态 | 首次注册 | 申请人更新时间 |
| --- | --- | --- |
| 默认 U001 人脸、指纹分别首次注册成功 | 人脸首次成功时间 | — |
| U301 旧数据有效 | 2026-11-12 09:00:00 | — |
| U301 新人脸成功 | 沿用 09:00:00 | 14:05:00 |
| U301 新指纹成功 | 沿用 09:00:00 | 14:08:00 |
| U302 重采完成 | 沿用 08:30:00 | 15:08:00 |
| U303 新人脸成功、指纹失败 | 沿用 10:00:00 | 16:05:00 |

“申请人列表 → 重采样例 → 三人旧数据有效 / 三人双模态删除 / 三人新人脸入库 / 三人重采结果”可复查各阶段。双模态删除后三人暂时退出列表；恢复新人脸后只展示有效新人脸，本轮新指纹成功后才出现新指纹。恢复默认数据返回 7 名有效人脸申请人及默认 15 条日志。

## 图像质量分

详情顶部使用与列表一致的“首次注册”“更新时间”。每张已入库人脸、指纹图像底部显示质量分条，分值来自该图像记录的 `qualityScore`，不从用户或指位推断。缺失显示“—”，有效数值 0 显示“0”；未入库指位只显示未入库，不生成分数。

打开 U001 可看到人脸 91 分；右手无名指为缺失质量分“—”，右手小指为有效 0 分。点击放大预览，质量分条及元数据中的质量分一致，并显示记录 ID、图像自身更新时间和指位。所有缩略图和放大图等比完整显示。

“三人重采结果 → U301 → 查看详情”中，左手食指有两条记录：原本轮记录 91 分、后写入的 duplicate 记录 97 分。列表和详情默认显示后者，详情可切换两条记录，图像和分值同步改变，放大预览仍使用当前选中记录。右手小指未采集，列表有占位、详情显示未入库。入库变更中的指位数仍为 9，“查看日志”仅跳转该次注册。
