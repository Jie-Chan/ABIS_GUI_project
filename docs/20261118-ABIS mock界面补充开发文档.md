## 3. 服务端取数与数据契约

### 3.1 扩展现有读取链路

**主机资源页 → `getHostResources()` → 同源 `GET /abis-admin/monitor/hosts` → Beszel Hub。** 在这次查询中一并读取内存缓存、Swap 和 CPU 分项，为最新样本及其近一小时历史补齐明细。沿用当前 60 秒轮询，悬停或点选时直接使用已返回的历史样本。

1. 服务端配置 Hub 地址、`121` 的系统 ID 以及能读取该系统的账号凭据。通过 `POST /api/collections/users/auth-with-password` 获取令牌，或复用工程已有合法会话。真实凭据在开发环境以服务端环境变量或现有密钥配置注入。仓库、`VITE_*` 变量、浏览器响应和日志中不得包含凭据。
2. 读取 `GET /api/collections/system_stats/records`。用 PocketBase 的 `filter` 同时限定 `system`、`type='1m'` 和 `created` 的近一小时时间窗，查询参数按 URL 编码。按 `created` 升序返回，可用 `perPage=100` 覆盖本次窗口。选择 `created` 及下表所列 `stats` 字段即可。使用服务端当前时间计算窗口，以 UTC 查询和传输。
3. 服务端只查询已配置的 `121`。浏览器使用原有 ABIS 访问方式，响应只返回下节约定的资源字段，不包含 Hub 令牌、原始记录全集或容器信息。沿用已有服务端监控权限校验。若使用 Vite 临时实现，按内网测试服务交付。
4. 本次保留同源接口 `{ items: [...] }` 的单机约定，只返回已配置的 `app-1`，含 `id`、`name`、`ip`、`sample` 和 `history`。`history` 按采集时间升序，`sample` 为最新一条。成功查询但时间窗为空，仍返回该主机及 `sample: null`、`history: []`。读取失败返回明确错误。前端将接口数据按稳定 `id` 合并到第 4.1 节的 8 台名录。未接入行来自名录，不向 Hub 发请求，不生成模拟记录。

实际请求可采用下列查询参数。`START_UTC` 和 `END_UTC` 在每次请求前换算为真实 UTC 边界，使用 PocketBase 的 `YYYY-MM-DD HH:mm:ss.SSSZ` 格式。通过查询参数构造器编码过滤表达式。

~~~text
GET /api/collections/system_stats/records
filter  = system = "vgrg02yzsr69lc7" && type = "1m" && created >= "START_UTC" && created <= "END_UTC"
sort    = created
perPage = 100
fields  = created,stats.cpu,stats.cpub,stats.mp,stats.mu,stats.m,stats.mem,stats.swap,stats.mb,stats.su,stats.s,stats.du,stats.d,stats.dp,stats.dio,stats.dios,stats.b
~~~

### 3.2 样本字段

`sample` 和每条 `history[]` 使用同一套字段。本次在两处各补充三个内存字段和三个 CPU 分项字段，类型均为 `number | null`。

| ABIS 字段 | Beszel `system_stats` 来源 | 含义 |
| --- | --- | --- |
| `collectedAt` | `created` | 样本时间，统一输出带时区的 ISO 8601 时间。 |
| `cpuPercent` | `stats.cpu` | CPU 总使用率，单位 %。总值直接取该字段。 |
| `cpuUserPercent`、`cpuSystemPercent`、`cpuIowaitPercent` | `stats.cpub[0]`、`stats.cpub[1]`、`stats.cpub[2]` | 依次为用户态、内核态、I/O 等待，原值均为百分数。按下标分别判空。 |
| `memoryPercent` | `stats.mp` | 内存使用率，单位 %。 |
| `memoryUsedGiB`、`memoryTotalGiB` | `stats.mu`、`stats.m` | 已用及总内存，原值单位 GiB。 |
| `memoryCacheGiB` | `stats.mem[2]`，兼容 `stats.mb` | 内存缓冲与缓存（buff/cache），界面标签为「缓存」。 |
| `swapUsedGiB`、`swapTotalGiB` | `stats.swap[1]`、`stats.swap[0]`，分别兼容 `stats.su`、`stats.s` | Swap 按「已用 / 总量」展示，单位 GiB。 |
| `diskPercent` | `stats.dp` | Beszel 上报的主文件系统使用率（%），用于概览。缺失时该格显示 `—`。 |
| `diskUsedGiB`、`diskTotalGiB` | `stats.du`、`stats.d` | 该 Agent 主文件系统的已用及总容量，单位 GiB。页面使用本次真实磁盘数据，省略旧 Mock 的业务挂载点。 |
| `diskReadBps`、`diskWriteBps` | `stats.dio[0]`、`stats.dio[1]` | 磁盘读取、写入速率，单位字节/秒（B/s）。 |
| `diskReadLatencyMs`、`diskWriteLatencyMs` | `stats.dios[3]`、`stats.dios[4]` | 分别为平均读取等待、平均写入等待，原值单位毫秒（ms）。两项各自判空，原数组缺失时两项均为 `null`。 |
| `netRxBps`、`netTxBps` | `stats.b[1]`、`stats.b[0]` | 网络接收、发送速率，单位 B/s。Beszel 原数组的顺序是先发送、后接收。 |

缓存和 Swap 优先读取字节数组，对应元素除以 `2³⁰` 转为 GiB。只有该元素缺失时才读取同一采样的兼容字段，兼容值的单位已是 GiB。逐项保留有效的 `0`，两处都缺失时返回 `null`。[Beszel v0.21.2 样本字段定义](https://github.com/henrygd/beszel/blob/v0.21.2/internal/entities/system/system.go#L19-L61)

**本次新增明细的核对样本。** 121 在 `2026-11-18T15:42:41.072Z`（北京时间 23:42:41）的记录中，缓存为 `15.53 GiB`，Swap 已用 / 总量为 `6.19 / 8.00 GiB`。同一时刻 CPU 总使用率为 `1.06%`，用户态 `0.66%`、内核态 `0.38%`、I/O 等待 `0.05%`。

**现场样本**采于 `2026-11-18T08:13:23.540Z`（北京时间 16:13:23）。CPU 为 1.17%，内存使用率为 44.96%，磁盘已用 419.89 GiB、总量 524.55 GiB。`dio=[0,206987]` 表示读取 0、写入 206987 B/s。`b=[30177,32838]` 表示接收 32838、发送 30177 B/s。该样本用于核对转换，运行时始终查询当时的近一小时。

延迟对照样本 `2026-11-18T09:43:41.033Z`（北京时间 17:43:41.033）的 `dios=[0.1,2.04,1.44,0.46,1.09,2.13]`。ABIS 应返回读 `0.46 ms`、写 `1.09 ms`。后续部署验收已核对主机接口的吞吐量和读写延迟。[Beszel v0.21.2 磁盘延迟计算](https://github.com/henrygd/beszel/blob/v0.21.2/agent/disk.go#L697-L726)

字段缺失时只将受影响的指标记为 `null`，合法值 `0` 原样保留。按采集时间去重，轮询或重试读到相同时间点时更新该点即可。采集字段可对照 [Beszel REST API](https://beszel.dev/zh/guide/rest-api) 和 [v0.21.2 版本字段定义](https://github.com/henrygd/beszel/blob/v0.21.2/internal/entities/system/system.go)。

- **磁盘切换。** 在同一张磁盘卡内切换「吞吐量 / 延迟」，同步更新曲线、纵轴、图例和悬停提示的单位，保持时间窗、容量读数及其他三图不变。延迟单位为 ms。单项缺失时只断开该线和对应填充。整窗无延迟数据时显示「暂无延迟数据」，仍可切回吞吐量。采样刷新保留当前选项。
- 指标或时间段缺失时，只在相应曲线留空，同时中断面积填充；有效的零值仍参与绘图。

### 4.3 采样与页面刷新

Beszel v0.21.2 的 Hub 默认约每 60 秒向已接入的 Agent 取一次系统指标，形成 `type=1m` 的历史样本。ABIS 主机页首次进入立即取数，随后用自己的 60 秒定时器重读同源接口。两个定时器独立运行，采样和页面读取的时刻可能错开。[Beszel v0.21.2 默认周期](https://github.com/henrygd/beszel/blob/v0.21.2/internal/hub/systems/system_manager.go#L32-L36)

2026-11-18 北京时间 17:00:41 至 17:59:41，`121` 返回 60 条采样，59 个相邻间隔平均 60.000 秒。页面显示时间统一取该主机最近有效样本的 `collectedAt`，转换为本地时间。收起详情时概览继续随页面轮询更新，展开时复用同一组数据。离开页面停止轮询。

| 本次读取结果 | 收起行、详情与操作 |
| --- | --- |
| 正常，有新鲜样本 | 收起行显示当前资源值，展开后在四图上方显示「采集于 HH:mm:ss」。 |
| 首次查询成功，尚无样本 | 该主机显示「暂无数据」，指标为 `—`，等待自动轮询。 |
| 已有有效快照，连续两个完整采样周期没有新点，或随后成功返回整小时空窗口 | 收起行直接显示「数据暂未更新 · 最后采集 HH:mm」。保留最后有效数值与时间，展开时展示该快照对应的历史窗口。即使响应为 HTTP 200、`sample: null`、`history: []`，也不清空旧快照。 |
| 读取请求失败 | 在该主机的错误提示旁显示「重试」，收起时也可操作。首次失败显示「读取失败」。已有快照时在该行保留「数据暂未更新 · 最后采集 HH:mm」、数值及可查看的历史曲线。 |
| 重试或自动轮询恢复成功 | 移除读取错误和「重试」。若从未取得样本且成功响应为空，显示「暂无数据」。已有快照且返回的仍是过期样本或空窗口时，继续提示「数据暂未更新」并保留旧快照。收到新鲜样本后恢复正常概览与详情。 |

「重试」只重读现有 ABIS 同源接口，不触发 Agent 即刻采样。将重试按钮与整行展开控件分开实现，点击重试保持当前展开状态及磁盘模式。重试期间沿用同一个轮询定时器，合并重叠请求或丢弃过期结果。
