# 服务状态监控卡片界面

本轮在 `front-end` 按审阅通过的客户版示意图实现。预览入口为 `http://10.200.51.121:5186/monitor`，仍使用 `npm run dev:mock -- --host 0.0.0.0` 启动，登录后查看。

## 展示内容

- 桌面两列、手机单列，保留六个服务对象的原始顺序；所有实例状态直接可见。
- 人脸、指纹服务使用中文名称，其他服务沿用接口返回的名称。名称映射仅在视图中进行，不改写数据。
- 顶部展示全量对象统计；「全部」「异常与不可达」筛选仅作用于展示列表，不改变总数，不请求新接口。
- 异常和不可达卡片以淡红色及左侧色条提示，未部署保持灰色且不计入异常。
- 算法服务仅展示底库规模和中文授权状态。CDC 字段不在卡片、详情或提示中展示，原接口字段仍保留。
- 底库规模为 0 时展示 0；缺失指标显示「未知」，授权状态展示「有效／无效／未知」。服务健康状态直接使用后端状态，不根据这些指标重新计算。
- 「上次成功刷新」与手动刷新集中在工具栏；刷新保留当前筛选。失败时保留旧数据与上次成功时间，明确提示读取失败，首次失败不生成虚假统计。

## 业务边界

只修改监控视图；API 适配器、Mock 数据、store、路由、权限与 60 秒轮询机制保持原样。此轮不修改 main 目录。

## 验证

工程根目录执行 `npm run build:mock`，在 `frontend-toolkit/verification/` 中执行 `npm test`。新增 `review-monitor.mjs` 构造 Mock 边界状态，检查卡片、筛选、读取失败、零值与未知状态，以及 320/390/767/768/1024/1280px 响应式布局和长文本。
