## 功能变化

- 日志首次进入和重置默认按接收时间倒序；点击时间表头在正序、倒序间切换。对全部匹配记录排序后分页，排序切换回第 1 页，CSV 使用同一份已生效条件及排序。
- 执行状态旁新增「失败」「待人工核查」快捷项，写入状态控件并按当前表单条件查询。再次点击已选项恢复全部；响应发布状态独立组合。查询失败仍保留上次成功结果及导出条件。
- 同一登录会话内保存日志已生效条件、排序、每页条数、页码和表格横纵滚动位置；未提交的输入草稿不作为返回状态。有关联条件的跳转优先使用关联条件，申请人变更日志仍精确到单次请求，支持返回原申请人页签和位置。退出或重新登录时清理日志及监控的导航状态。
- 服务状态的「异常」「未知」筛选及页面滚动位置在前往主机资源后可恢复，兼容浏览器返回和监控菜单返回。返回时重新获取监控数据并计算筛选结果，继续突出所定位的主机。
- `REQ-00000008` 首屏业务摘要明确显示「等待 ABIS 响应超时，执行结果未确认。」及核查指引，保留错误码和定位超时事件的「查看事件」。请求 ID 旁新增复制入口及成功/失败反馈，普通 HTTP 访问也可复制。
- 补充历史样例 `REQ-00000018`（申请人 `U018`），用于验收已知执行结果未确认、原因缺失的情形。按请求 ID 查询可访问；不新增到默认 15 条日志，不产生有效入库记录，不推断超时原因。
- 1024 × 768 主筛选区收起时保持三行，请求/申请人 ID、时间、两类状态、快捷项和查询/重置直接可用；接口及模态放入更多筛选，收起后显示已生效附加条件数量。表格首列依次优先显示请求 ID、接收时间、执行状态、响应发布状态，右侧固定详情入口，其余字段可横向滚动。1280 和 624 保留原有宽屏/窄屏筛选方式。
- 日志筛选、列表、详情、事件、比对图像及 CSV 统一使用「申请人 ID」，原始 JSON 字段名仍为 `userId`，缺少该值显示「—」。
- 人脸分值条标注「质量分」，指纹组共用一处标注。缺失分值显示「—」，悬停及键盘聚焦均提示「质量分未提供」，无障碍名称同步表达；实际 0 分保留。缩略图及放大图使用同一记录的分值。
- 登录失败审计在结果附近显示允许呈现的失败类别；样例同时覆盖「凭据校验失败」和「未记录」。变更类审计继续并列展示变更前后值。

## 验收入口

使用 `npm run dev:mock -- --host 0.0.0.0`，访问服务器 5186 端口；管理员 `admin / admin123`。

1. 日志默认 15 条，请求 ID 从 `REQ-00000015` 到 `REQ-00000001`。按 `U001` 查询共 4 条，切换审计后返回可继续原查询；用 5 条/页验证多页及排序恢复。
2. 快捷项「失败」对应 `REQ-00000011`，执行失败但响应已发布；「待人工核查」对应 `REQ-00000008`，暂无最终响应。打开详情核对摘要、复制及查看事件。原因缺失用 `REQ-00000018`；申请人 ID 缺失用 `REQ-00000016`。
3. 申请人 `U001` 的指纹注册日志只跳到 `REQ-00000002`。当前图像右手无名指为缺失质量分，右手小指为 0 分。
4. 服务状态筛选异常后从 `face-1` 定位算法 VM 1，未知后从 `minio-1` 定位 MinIO VM；分别通过浏览器和监控菜单返回。
5. 审计筛选「登录」「失败」，前两条记录分别核对已记录失败类别和未记录；切到修改匹配阈值核对前后值。

## 会话验收结果（§9.6）

路由启动时，有已有凭据则先通过 `getSession` 确认账户再进入受保护页面；不以本地 token 存在直接判定已登录。失效时清理凭据及导航缓存，回到登录并保留原访问地址。

| 场景 | 验证方式 | 结果 |
| --- | --- | --- |
| 有效会话，刷新服务状态与日志查询 | 通过现有 `getSession` 契约注入有效账户，不连接真实服务 | 两个页面刷新后保持登录并停留原路由 |
| 失效会话，访问/刷新两个受保护页面 | 契约注入会话失效错误 | 清理本地凭据，转到登录并保留原地址 |
| 当前 Mock 实际刷新 | 使用现有模块内存会话 | 刷新后内存会话重置，回到登录；种子数据和改密演示规则保持 |
| 正式环境真实有效/失效会话 | HTTP 管理 API 适配器尚为未实现占位 | 尚未执行正式联调验收；需接通真实 `getSession` 和既定会话策略后验证，不能用契约样例结果代替 |
