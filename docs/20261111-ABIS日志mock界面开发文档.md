# ABIS GUI 请求日志 Mock 开发说明

版本日期 2026-11-11

请在当前服务器的 GUI Mock 工程中完善已有的请求日志页面。沿用现有页面入口、组件和视觉风格，交付可交互的「请求列表 + 右侧详情抽屉」。用本地虚构数据模拟请求、Stage 和 Event。人工核查在本轮只做状态和事件展示。本文包含开发和验收所需的规则。

## 1. 请求列表

每次接口调用对应一条逻辑请求，使用独立的 `requestId`，在列表占一行。默认先按 §3 展示异步的用户业务流程和独立异常，再展示同步正常样例。同一用户的注册、查重、删除按业务发生顺序排列，每行可独立打开详情。

| 字段 | 展示规则 |
| --- | --- |
| 请求 ID `requestId` | 唯一标识逻辑请求。MQ 重投、调用重试和发布重试都归入原请求。 |
| 用户 ID `userId` | 被注册、识别或删除的业务对象 ID。Mock 的查重请求携带本次待查对象 ID。若客户接口约定允许省略 `userId`，GUI 显示「—」，可按 `requestId` 查找。命中的候选人 ID 留在响应详情。 |
| 接口类型 | 至少覆盖 `enrollment`（注册）、`identification`（识别）、`delete`（删除）。同步与异步的同一业务操作映射到相同类型。 |
| 接收时间 | 同步取 ABIS 收到请求的时间，异步取适配服务首次收到请求 MQ 消息的时间。 |
| 当前阶段 | 优先显示此刻阻塞任务执行或响应交付的阶段。正常推进时显示实际进展最靠后的阶段。 |
| 执行状态 | 显示执行进展或明确业务结果。执行结果不明时显示「待人工核查」。 |
| 响应发布状态 | 异步显示「待发布」「已发布」或「暂无最终响应」。同步显示「—」。 |
| 请求耗时 | 完成最终响应时显示总耗时。处理、待核查或待发布时，显示从收到请求到当前的「已用时」。 |

支持按 `requestId` 或 `userId` 查找，并与接口类型筛选组合使用。列表和详情顶部使用同一套取值规则。同步请求从 ABIS 的「接收请求」Event 取 `userId` 和接口类型，异步请求从适配服务的「接收请求」Event 取值。异步请求的两条接收 Event 分别保留，ABIS 入口 Event 迟到时，列表和详情仍以适配服务入口的字段为准。

ACK 异常发生后，若 Worker 已开始调用 ABIS，当前阶段显示「调用 ABIS」。若响应发布失败正在等待重试，当前阶段显示「发布响应」，执行状态保留已确认的业务结果。响应重试成功后显示最后完成的阶段。若 ABIS 明确返回业务失败且失败响应已经交付，当前阶段显示「ABIS 处理」，执行状态显示「失败」。历史异常保留在抽屉中。

## 2. 右侧详情抽屉

点击列表行，从右侧打开抽屉。关闭后保留筛选条件和列表滚动位置。顶部显示请求 ID、用户 ID、接口类型、接收时间、执行状态、响应发布状态和请求耗时。

| 链路 | 默认展示 |
| --- | --- |
| 同步 | 一个「ABIS 处理」Stage，代码为 `ABIS_HANDLING`。 |
| 异步 | 「适配服务接收请求」`ADAPTER_RECEIVED` →「调用 ABIS」`ADAPTER_CALLING` →「发布响应」`ADAPTER_RESPONDED`。展开「调用 ABIS」可查看适配服务的调用 Event 和内嵌的「ABIS 处理」。 |

各 Stage 独立显示状态、起止时间和耗时。展开后按实际发生时间展示 Event，包含动作、时间、结果及已记录的错误码和描述。多次投递、调用或发布尝试在原 Stage 下分别显示。

### ABIS 处理与查看响应

「ABIS 处理」展开后显示三项 **接收请求 → 业务处理 → 发送响应**。业务处理开始和结束分别记录时间，界面合成一项展示。

在「发送响应」旁提供**查看响应**按钮，点击后在当前抽屉内展开所选 Event 对应的 ABIS 接口响应正文，JSON 按格式化展示。没有已记录的正文时显示「暂无 ABIS 响应内容」。请求存在多次尝试时，按 `requestId` 和选中的发送响应记录定位正文。

### 状态与重试

- Stage 用 `WAITING`、`RUNNING`、`SUCCESS`、`FAILED`、`UNKNOWN`。确定不会执行的阶段显示「不适用」。Event 用 `STARTED`、`SUCCESS`、`FAILED`，记录当次动作的结果。
- `ADAPTER_RECEIVED` 以任务可靠落库为完成点。请求 ACK 单独记录。ACK 发送异常后如果 MQ 重投，在同一请求下依次保留「ACK 发送异常」「重复投递」「发送请求 ACK」，接收 Stage 仍为 `SUCCESS`。
- Worker 有执行槽位后，将任务从 `PENDING` 原子更新为 `CALLING` 并提交，再开始调用。`ADAPTER_CALLING` 的开始时间取实际调用尝试的 Event。确认请求未发出、故障可重试且仍有额度时，任务可退回 `PENDING`，调用 Stage 提示「待重试」。
- 请求可能已发出且结果不明时，`ADAPTER_CALLING` 显示 `UNKNOWN`，请求显示「待人工核查」，响应栏显示「暂无最终响应」。若随后采到 ABIS 内部日志，在内层按各自证据展示。
- `ABIS_HANDLING` 结束后按明确的 ABIS 业务结果判定。若业务失败但 ABIS 成功发出响应，`ABIS_HANDLING` 为 `FAILED`，「发送响应」Event 为 `SUCCESS`。适配服务收到可解析的响应后，`ADAPTER_CALLING` 为 `SUCCESS`。1:N 正常完成且候选列表为空时，按正常业务结果展示。
- `ADAPTER_RESPONDED` 在响应通过约定路由、获得 MQ 发布确认且未被退回后显示 `SUCCESS`，响应发布状态显示「已发布」。发布失败时按已知结果展示「待发布」或「待重试」。重试发送已保存的响应，详情保留各次发布结果。
- 日志采集延迟时提示「日志可能尚未齐全」。按已有证据展示状态，保留迟到的历史 Event。已确认的阶段成功状态保留。

### 耗时

| 指标 | 计算 |
| --- | --- |
| 同步请求总耗时 | ABIS 收到请求到服务端完成响应发送。 |
| 异步请求总耗时 | 适配服务首次收到请求 MQ 消息到最终响应通过约定路由并获得可靠发布确认。包含内部等待和重试。 |
| Stage 耗时 | 本阶段首次开始到确认结束。包含阶段内重试及等待。已完成的接收阶段耗时按任务可靠保存时截点计算。 |
| 「ABIS 处理」阶段耗时 | ABIS 收到请求到服务端结束响应发送，包含入口处理、业务处理和响应发送。 |
| ABIS 实际处理耗时 | 同一次业务处理的开始到结束。若有多次实际执行，按次展示。 |

异步抽屉可同时显示外层调用耗时和内层两种 ABIS 耗时。使用 Event 发生时间，各 Stage 时间可以重叠，请求总耗时按请求自身的起止点计算。已结束指标缺少起止点或时间顺序无效时显示「无数据」。

## 3. Mock 样例

默认按下面的顺序展示，共 11 条请求。每行使用独立的 `requestId`。同一用户的多次接口调用使用同一个 `userId`。样例体现业务系统发起后续请求的顺序，日志页面展示已发生的请求和事件。

### 异步业务流程

| 顺序 | 用户 ID | 接口 | 展示与核验 |
| --- | --- | --- | --- |
| 1 | `U001` | 注册 `enrollment` | 注册成功，响应已发布。可展开「调用 ABIS」下的「ABIS 处理」和三项 Event，并查看成功响应。 |
| 2 | `U001` | 查重 `identification` | 查重成功，候选列表为空，业务流程完成。 |
| 3 | `U002` | 注册 `enrollment` | 注册成功，响应已发布。 |
| 4 | `U002` | 查重 `identification` | 查重成功，命中已有用户 `U001`。列表的用户 ID 为待查对象 `U002`，响应详情可看到候选人 `U001`。 |
| 5 | `U002` | 删除 `delete` | 删除本次新注册的 `U002`，显示删除成功。已有用户 `U001` 仍是查重候选人。 |
| 6 | `U003` | 注册 `enrollment` | 等待 ABIS 响应超时且结果不明。当前阶段为「调用 ABIS」，执行状态为「待人工核查」，暂无最终响应。该用户的流程停在注册，列表只有这一条请求。 |

### 异步查重异常

以下用户按已注册准备数据，每个用户只展示一条本次查重请求。

| 顺序 | 用户 ID | 接口 | 展示与核验 |
| --- | --- | --- | --- |
| 7 | `U004` | 查重 `identification` | 任务落库后 ACK 发送异常，随后收到 MQ 重投。接收 Stage 保持 `SUCCESS`，查重照常推进。列表只有一条请求，详情保留 ACK 异常、重复投递和本次发送 ACK。 |
| 8 | `U005` | 查重 `identification` | 获取 HTTP 连接超时，已确认本次请求未发出。「调用 ABIS」显示「待重试」，详情记录失败原因及未发送的判定依据。 |
| 9 | `U006` | 查重 `identification` | ABIS 明确返回查重失败，失败响应已交付。列表当前阶段为「ABIS 处理」。内层为 `FAILED`，发送响应 Event、外层「调用 ABIS」和「发布响应」为 `SUCCESS`。可查看失败响应正文。 |
| 10 | `U007` | 查重 `identification` | ABIS 查重成功，响应发布失败并等待重试。执行状态为成功，当前阶段为「发布响应」，响应状态为「待发布」，请求耗时显示「已用时」。 |

### 同步正常样例

| 顺序 | 用户 ID | 接口 | 展示与核验 |
| --- | --- | --- | --- |
| 11 | `U008` | 删除 `delete` | 同步删除成功。顶层只显示一个「ABIS 处理」，展开可见接收请求、业务处理、发送响应。响应发布状态为「—」，可查看成功响应正文。 |

可用 `U001` 的注册请求校验耗时。适配服务在 0 ms 收到消息，ABIS 在 70 ms 收到请求，90 ms 开始业务处理，210 ms 结束业务处理，250 ms 完成响应发送，320 ms 获得最终响应发布确认。预期总耗时为 320 ms，「ABIS 处理」阶段耗时为 180 ms，ABIS 实际处理耗时为 120 ms。

## 4. 交付验收

1. 实际打开 GUI 日志入口。默认依次展示 `U001` 至 `U003` 的异步业务流程、`U004` 至 `U007` 的异步查重异常、`U008` 的同步样例，共 11 行。
2. 按 `userId` 分别查询 `U001`、`U002`、`U003`，核对返回 2 条、3 条、1 条请求。确认 `U002` 的查重候选人是 `U001`，删除请求的对象是 `U002`。核对 `requestId` 查找、接口类型筛选，以及 `userId` 缺失时的展示规则。
3. 核对同步和异步的 Stage 层级、入口字段取值、抽屉关闭后保留列表上下文，以及「查看响应」打开的正文与所选 Event 一致。
4. 核对 `U004` 至 `U007` 的异常展示，并用 `U001` 的注册请求核对三种耗时。
5. 交付时列出修改的文件、页面预览入口和已实际验证的交互。
