# ABIS Mock 界面开发文档

版本日期 2026-11-13

本次更新接续 [[20261112-ABIS mock界面开发文档]]，按界面记录日志查询、申请人列表、服务状态监控、审计查询和匹配阈值配置的开发要求及验收项。本轮调整三处查询页的白色主内容区、筛选栏吸附和日期选择，完善日志排障与查重图像、申请人与日志联动、监控布局与主机定位，以及审计筛选和阈值校验。

界面文案采用真实管理控制台的业务用语。登录页、顶部导航、列表、抽屉、弹窗、图像及页脚统一移除 Mock、演示环境和本地虚构数据等说明，包括演示标识、演示账户说明、演示数据日期范围、图像来源于 Mock 的技术说明及密码刷新后恢复等演示行为提示。开发样例、验收账号、数据范围及状态切换方式记录在开发或交付说明中。业务字段、操作提示、空状态、质量分及查重图像时点提示按实际功能展示。各页需清理的具体文案及验收方式见 §6.1、§6.2。

## 1. 日志查询界面

### 1.1 查重图像比对

查重请求的「图像比对」使用独立标签页。抽屉的标签顺序和默认页见 §1.5。

「图像比对」左侧标题为「待查图像」，右侧标题为「候选图像」，分别展示待查对象和选中候选的图像。图像下方分别标注各自的用户 ID。候选排名和比对分数取本次请求的 ABIS 响应，放在右侧图像上方，并在两项旁标注「本次响应」。指纹案例在左右图像标题旁分别标注对应指位，例如「左手食指」。两侧图框保持等高并采用紧凑间距，图框高度随「图像比对」标签页的剩余空间调整，为图像下方的用户 ID 预留完整一行。图像等比完整显示，在 1422 × 804 和 1280 × 720 的桌面视口首屏同时看到两张图像、用户 ID、分数及指纹指位。候选按钮按本次响应中的顺序排列，文案仅显示「候选 1」「候选 2」等序号。候选用户 ID 显示在右侧图像下方。切换候选时保留左侧图像。

窄屏下，待查侧与候选侧使用相同的标题区高度，图像标题和指位的起点、两侧图框的上边缘分别对齐。「本次响应」、候选排名和比对分数放在候选侧标题下方的独立信息行。信息换行时，两侧标题区按较高的一侧同步增高，待查侧保留对应空间。切换候选时保持两侧标题和图框的位置稳定。

本阶段沿用现有图像存储，通过 GUI 后端按用户 ID 查询 ABIS PostgreSQL 中的 MinIO 图像链接，再获取图像供界面展示。左侧用户 ID 取本次请求的待查对象 `userId`，右侧取本次查重响应中对应候选的 `userId`。按请求的生物模态以及已有的部位信息定位对应图像。Mock 使用本地虚构数据模拟该取图过程。

待查图像可用时照常显示。右侧优先展示已确认的查重结果。明确失败时显示「本次查重失败」，成功且响应明确返回空候选列表时显示「本次查重无候选」。响应待发布时仍按已确认的业务结果展示。仍在排队、等待调用重试或执行时显示「查重处理中」，其他缺少可用查重结果的情况显示「暂无查重结果」。空状态在右侧图框内居中，使用低对比度图标和中性文字。左右图框保持一致的背景和间距。

用户记录或图像链接缺失时，在对应图像位置显示「暂无可用图像」。确认对象已删除时显示「图像已删除或不存在」，临时读取失败时显示「图像加载失败」。保留对应用户 ID 和本次响应记录的候选信息。

图像页顶部统一提示「图像取自当前入库记录，可能与查重时不同。」

点击任一已加载的图像可放大查看，预览中保留图像对应的用户 ID，指纹同时显示指位。图像等比完整显示，关闭预览后回到当前候选的比对画面。

> [!warning] 历史图像一致性
> 此方案按用户 ID 查询当前 ABIS 数据库和 MinIO 中的图像。请求对象或候选对象更新图像后，历史查重记录可能展示更新后的图像。用户记录、图像链接或 MinIO 对象删除后，历史记录中的对应图像可能无法读取。本次查重的候选和分数仍取原响应，图像仅供辅助查看。

### 1.2 请求列表字段与接口类型

请求 ID 列放在用户 ID 列前面，依次作为列表第一列和第二列。每条请求都有请求 ID，用户 ID 缺失时显示「—」，该请求仍可通过请求 ID 查询并打开详情。

在「接收时间」后增加「请求来源 IP」列，显示发起这条业务请求的调用方 IP。同步请求使用 ABIS 接收请求时记录的原始调用方 IP。异步请求使用上游随请求传递并记录的原始发起方 IP。MQ Broker、适配服务和重试节点的 IP 属于处理链路信息。原始发起方 IP 未记录或无法确认时显示「—」。Mock 使用虚构 IP 覆盖同步、异步及缺失三种样例。

查重接口的界面名称统一为「1：N查重」。接口类型筛选项显示「1：N查重」，匹配指纹和人脸两种模态。列表和抽屉中保留模态，显示「指纹 1：N查重」或「人脸 1：N查重」。

在 1422 × 804 和 1280 × 720 的桌面视口，列表初始横向位置同时显示完整的请求 ID、处理环节、执行状态、响应发布状态和请求耗时。按字段内容调整列宽和换行，给右侧固定的操作列预留空间。纵向滚动时，筛选栏和其下方的表头保持可见，表头与表格内容的列线始终对齐。

### 1.3 处理环节名称与展示

将请求列表的「当前阶段」列改名为「处理环节」。列表显示中文名称，Stage 英文代码在抽屉中展开对应阶段后展示。列表与抽屉的阶段标题使用同一套中文名称。

| Stage 代码 | 中文名称 | 含义 |
| --- | --- | --- |
| `ADAPTER_RECEIVED` | 接收请求 | 适配服务接收请求并可靠保存任务。 |
| `ADAPTER_CALLING` | 调用 ABIS | 适配服务发起调用并等待 ABIS 响应。 |
| `ABIS_HANDLING` | ABIS 处理 | ABIS 执行注册、查重、删除等业务。 |
| `ADAPTER_RESPONDED` | 发布结果 | 适配服务保存结果并发布到响应 MQ。 |

「处理环节」沿用既有阶段选择规则。处理中优先显示阻塞任务执行或响应交付的环节，正常完成后显示最后完成的环节。发生异常时显示需要关注的环节，业务失败且失败响应已交付时显示「ABIS 处理」。执行状态和响应发布状态分别说明业务执行结果及响应交付情况。

异步阶段顺序显示为「接收请求 → 调用 ABIS → 发布结果」，「ABIS 处理」位于对应调用尝试内部。同步请求显示「ABIS 处理」。注册、查重、删除由接口类型表达。

### 1.4 多候选查重与补充日志样例

在原有 13 条请求后追加以下两个异步查重案例，共展示 15 条请求。每个新增案例返回 3 名候选，使用本地虚构图像和响应数据，执行成功且响应已发布。

| 请求 ID | 待查用户 ID | 接口类型 | 按响应顺序返回的候选用户 ID | 业务结果摘要 |
| --- | --- | --- | --- | --- |
| `REQ-00000014` | `U009` | 指纹 1：N查重 | `U101`、`U102`、`U103` | 查重成功 · 候选 3 条 |
| `REQ-00000015` | `U010` | 人脸 1：N查重 | `U201`、`U202`、`U203` | 查重成功 · 候选 3 条 |

两个案例均提供可正常读取的待查对象图像和三名候选图像。指纹案例采用同一指位的待查及候选指纹，沿用已有指位标识；人脸案例提供待查及候选人脸图像。按现有 Mock 接口的分值范围配置三名候选的递减示例分数，候选 ID、排名、分数和图像关联在响应 JSON 与「图像比对」页中保持一致。

每次打开请求详情后，首次进入「图像比对」页时默认选中排名第一的候选，候选按钮显示「候选 1」「候选 2」「候选 3」及当前选中状态。逐一切换时，右侧图像、用户 ID、排名和分数随之更新，左侧待查图像及其用户 ID 保持可见。同一次打开请求详情期间，切换到其他标签页后再返回时保留选中的候选。两个案例均显示图像来源提示。

#### 补充日志验收样例

默认列表展示既有 15 条请求。已生效的查询条件中请求 ID 和用户 ID 均为空时，筛选条件作用于这 15 条请求，默认数据范围由本节说明，用于开发与验收。填写任一 ID 并执行查询时，在已有请求、历史样例及补充验收样例中匹配 ID，同时应用其他已提交的筛选条件。

| 请求 ID | 场景 | 预期展示 |
| --- | --- | --- |
| `REQ-00000016` | 已记录请求 ID，缺用户 ID | 用完整请求 ID 查到该记录。列表及详情的用户 ID 显示「—」，请求详情可正常打开。 |
| `REQ-00000017` | 同一异步请求有两次 ABIS 调用尝试 | 第一次获取连接超时，确认请求尚未发送，第二次调用成功并记录请求和响应正文。时间线按尝试编号展示，接口报文分别显示第一次的正文缺失提示及第二次的请求参数和响应结果。 |

### 1.5 抽屉信息表格与分区

抽屉标题统一使用「请求详情」。请求详情与申请人详情共用顶部间距规则，从抽屉标题区域下边缘到首块信息表格上边缘统一留 16～20 px，标题区域外边距和内容区顶部内边距合计计入该距离。顶部信息表格与下方详情区等宽、左右对齐，中间留约 20 px 间距。表格使用细浅边框和浅色字段背景，保持紧凑行距。

异步请求的信息表格按以下顺序排布。通栏行的字段名占左侧标签格，内容合并右侧三格。

| 行 | 左侧字段与内容 | 右侧字段与内容 |
| --- | --- | --- |
| 1 | 请求 ID，通栏展示 | 合并至左侧内容 |
| 2 | 用户 ID | 接口类型，包含模态及同步／异步标识 |
| 3 | 接收时间，通栏展示完整日期及毫秒 | 合并至左侧内容 |
| 4 | 执行状态 | 响应发布状态 |
| 5 | 请求总耗时；进行中的请求按既有口径显示「已用时」 | ABIS 接口处理耗时 |
| 6 | 业务结果摘要，通栏展示 | 合并至左侧内容 |

同步请求的信息表格省去响应发布状态，耗时仅展示请求总耗时。同步的请求总耗时与 ABIS 接口处理耗时按同一口径计算。字段按剩余空间紧凑排列。移除旧「ABIS 实际处理耗时」及业务处理 Event 中对应的单独用时数值（如 `120 ms`）。业务处理 Event 保留起止时间、结果和异常信息。

业务结果摘要显示当前需要处理的问题。业务失败、等待重试、待人工核查或响应待发布时，摘要结合已记录的执行结果和当前环节给出简短说明。有当前尚待处理的异常事件时，在摘要旁显示对应的错误码和「查看事件」入口。点击后切到「处理过程」，展开对应阶段及调用尝试并定位该事件，其他阶段保留用户设置的展开状态。缺少具体事件时，摘要展示已知状态。`REQ-00000012` 显示「查重成功 · 响应待发布」，可从摘要定位 `PUBLISH_NACK`。`REQ-00000011` 显示「查重失败 · 失败响应已发布」。重试后业务成功且响应已发布时，摘要显示「查重成功 · 重试后完成」。已恢复的错误保留在对应调用事件中；顶部需要提供追溯入口时，标明「历史异常」，点击后定位对应调用及事件。`REQ-00000017` 第一次调用的 `CONNECT_TIMEOUT` 按此规则展示。

下方详情区使用浅色边框包住标签栏和当前页内容。标签栏位于详情区顶部。查重请求依次显示「处理过程｜接口报文｜图像比对」，其他请求依次显示「处理过程｜接口报文」。打开抽屉默认进入「处理过程」，顶部信息表格在各标签页中均可见。选中项用主题色文字和下划线突出。标签栏背景与表格字段背景使用同一档浅灰色，内容区以白色为主，内部留约 16 px 边距。通过表格、间距和详情区边框形成上下分区。抽屉标题、表格字段和标签名称承担标题层级。

### 1.6 ABIS 接口报文

「接口报文」是独立标签页，设置「请求参数」「响应结果」两项。首次进入该标签页时两项默认展开，点击整行标题可分别展开或折叠。切换标签页时保留用户手动调整的展开状态。

「请求参数」展示实际发送给 ABIS 接口的请求正文，「响应结果」展示对应的 ABIS 响应正文。JSON 格式化显示，使用浅灰背景。请求参数和响应结果各自使用可滚动的代码区域，较长的正文在对应区域内滚动。

有多次 ABIS 调用尝试时，按尝试编号对应各次请求参数与响应结果。缺少已记录正文时，展开后分别显示「暂无请求参数记录」或「暂无响应正文记录」。Mock 为对应调用尝试补充本地虚构的请求参数和响应正文。

### 1.7 阶段默认展开方式

「处理过程」页直接展示阶段标题和时间线，省去额外的「阶段概览」标题。同步请求的单一「ABIS 处理」阶段直接显示接收请求、业务处理、发送响应三个 Event，标题右侧显示状态和耗时，下面显示阶段代码及紧凑起止时间。同步详情压缩标题与信息表之间的留白及事件行间距。在 1422 × 804 和 1280 × 720 的桌面视口首次打开时，无需滚动即可看到「接收请求」「业务处理」「发送响应」三个事件标题，较长的说明可在时间线内滚动查看。

首次打开请求详情时，所有顶层阶段默认展开。同步请求展开顶层「ABIS 处理」，异步请求展开「接收请求」「调用 ABIS」「发布结果」。异步「调用 ABIS」内嵌的「ABIS 处理」默认折叠，折叠行显示阶段名称、状态和耗时，点击后查看内部事件。各请求状态均采用同一规则，历史异常保留在对应 Event 中。

阶段采用紧凑的时间线行，左侧保留节点和连线，右侧的状态、耗时和展开箭头分别对齐。展开后显示时间和事件。调用方放在对应的接收请求事件详情中，生物模态由顶部接口类型表达，人工核查提示放在需要核查的状态旁。

用户可手动展开或折叠阶段，切换标签页后保留其选择。

顶部请求信息表格和标签栏固定在抽屉顶部。「处理过程」的时间线区域按当前窗口的剩余可用高度限制最大高度。内容超出时，仅时间线区域纵向滚动，鼠标指针位于时间线上即可用滚轮查看其余事件。内容较少时自然显示。

### 1.8 页面标题与紧凑筛选栏

移除页面内容区独立的图标、「日志查询」大标题和「按请求或用户追查处理阶段、事件与响应结果」说明文字。顶部导航通过高亮的「日志查询」标识当前页面，内容区从筛选栏开始。

桌面宽度下，筛选栏按以下顺序紧凑排列为两行，全部筛选条件默认可见。

| 行 | 第一列 | 第二列 | 第三列 | 第四列 | 右侧操作 |
| --- | --- | --- | --- | --- | --- |
| 第一行 | 请求 ID | 用户 ID | 时间范围（开始时间至结束时间） | | |
| 第二行 | 接口类型 | 生物模态 | 执行状态 | 响应发布状态 | 查询、重置 |

两行共用列线。前三列各自的上下两行字段名左对齐，控件起点也左对齐。第一行的时间范围可横跨第三、第四列。字段名位于控件左侧并垂直居中。下拉框按选项文本设置紧凑宽度，ID 和时间范围按完整值的输入需要分配空间。查询和重置放在第二行最右侧，缩小筛选栏上下留白和行间距。

「响应发布状态」可与执行状态及其他条件组合。选「全部」时，同步和异步请求按其他条件参与查询。选择「已发布」「待发布」「暂无最终响应」等具体状态时，匹配对应的异步请求。

在约 624 px 的窄屏下，筛选区默认显示请求 ID、用户 ID、时间范围和「查询」「重置」。接口类型、生物模态、执行状态和响应发布状态放入「更多筛选」。收起后继续应用已生效的附加条件，并在入口显示其数量。

移除总耗时区间筛选。日志列表继续展示「请求耗时」列。

申请人列表、日志查询和审计查询的内容区依次为筛选栏、表格和底部分页区。筛选栏下方直接显示表头，移除原数量说明行、导出工具条及其占位。查询结果总数仅在底部分页区显示，随已生效的查询结果更新。日志查询和审计查询将「导出 CSV」置于底部左侧，总数和分页控件置于同一行右侧。申请人列表底部仅显示右对齐的总数和分页控件。滚动表格记录时，底部操作保持可见。日志 CSV 的「接收时间」与列表使用相同精度，按 `YYYY-MM-DD HH:mm:ss.SSS` 导出，表头及数据行移除旧「ABIS 实际处理耗时」列。

日志查询与审计查询的列表、结果数量、分页和 CSV 使用同一份已生效的查询条件。执行查询或重置且结果更新后，导出随结果更新。仅编辑筛选控件时，列表及导出仍对应上一次已生效的查询结果。导出覆盖该结果的全部分页。

## 2. 申请人列表界面

### 2.1 页面布局与列表

移除内容区独立的图标、「申请人列表」大标题和用途说明。顶部导航高亮「申请人列表」，内容区从筛选栏开始。桌面端将申请人 ID、首次注册时间范围、查询和重置排在同一行。筛选栏按 §1.8 的规则固定在顶部导航下方，表头按同节的三页共用规则固定在列表区域顶部。

筛选栏下方直接显示申请人表头。申请人数量仅在底部分页区显示，移除范围说明「仅展示已确认注册成功且当前有效的申请人」。以当前有效的人脸注册记录作为申请人进入列表的条件，指纹允许缺采。

列表按「申请人 ID｜人脸｜指纹｜首次注册｜更新时间｜操作」排列。操作列只保留「查看详情」，两个时间列均支持排序。

- **人脸**展示一张当前有效的人脸缩略图，等比完整显示。缩略图仅作展示，通过操作列的「查看详情」打开抽屉。
- **指纹**展示当前有效的图像，按左手 5 格、右手 5 格排列，两手之间留出间距。桌面端优先横排十指，窗口较窄时按左右手各排一行。每个格子绑定固定指位，未采集的指位保留占位，悬停可查看指位和状态。有有效记录但图像不可用时显示「图像不可用」。同一指位有多条有效记录时，列表和详情抽屉的「当前入库图像」统一展示最新一条有效记录。按成功入库时间确定最新记录，同一入库时间时按写入顺序取最后一条。缩略图组旁显示按当前有效记录去重后的指位数，例如「8/10 指」。没有有效指位时显示「指纹未入库」。
- **首次注册**取同一 `userId` 第一次人脸注册成功的时间。整人重采后沿用原 `userId` 和原首次注册时间。Mock 数据需保留这个历史时间。
- **更新时间**取首次采集完成后最近一次成功改变有效入库数据的注册或删除时间。首次采集的人脸和指纹即使分两次注册，也都计入首次采集，只有首次采集的申请人显示「—」。Mock 数据明确标记首次采集与后续重采轮次。查重和失败请求保留在请求日志中，更新时间沿用上一次成功变更的值。

按完整申请人 ID 查询且结果为空时，空态提供「按此 ID 查看请求日志」。点击后将已查询的 ID 带入日志查询的「用户 ID」并执行查询，以便查看注册、删除或失败请求。

### 2.2 申请人详情抽屉

抽屉提供「当前入库图像」和「入库变更记录」两个标签页，默认打开「当前入库图像」。标题区域至首块信息表格的间距按 §1.5 控制在 16～20 px。

**当前入库图像**

展示当前有效的人脸和指纹图像。桌面端将「申请人 ID」「首次注册」「更新时间」紧凑排在一行，字段名称、取值和「更新时间」为空时显示的「—」均与列表一致。图像区左侧展示当前有效的人脸，右侧按左手、右手及指位顺序排列当前有效的指纹卡片。每手最多展示 5 个指位。窗口较窄时允许换行，抽屉内容区可纵向滚动。

- 只为当前有效入库的指位渲染卡片，卡片展示指位和缩略图。全部指位都没有有效记录时，在指纹区域显示一处「未入库」。已有记录但图像加载失败时显示「图像不可用」。同一指位只展示最新一条有效记录，卡片直接显示对应图像。指纹区标题按去重后的有效指位数显示，例如「指纹 8 指」。移除旧「2 条」标记、记录选择下拉框及「9 条记录」汇总。
- 抽屉内每张人脸和指纹缩略图的下方显示质量分条，参考示例图的底部色条布局，直接显示该图的分值，例如 `91`。质量分与最新一条有效记录的图像绑定，缩略图和放大预览的图像、质量分及图像更新时间对应同一次有效入库。
- 已入库图像没有质量分时，分值显示「—」。有分值时按记录原值展示，`0` 显示为 `0`。Mock 使用各图像记录配置的样例分值。
- 点击任一缩略图可放大，放大预览中显示申请人 ID、图像更新时间和同一质量分，指纹同时显示指位。缩略图和放大图均将图片宽高约束在各自的预览框内，使用 `object-fit: contain` 等比完整显示，确保图像边缘可见。

沿用现有图像数据和预览入口，调整抽屉布局与图像样式。

申请人图像放大预览弹窗的总高度须适配当前视口，上下外边缘各保留至少 16 px。标题和关闭操作始终可见，图像按剩余空间等比缩放。内容超出可用高度时，由弹窗内容区滚动，页脚关闭按钮保持可操作。窗口高度变化时重新计算可用空间。

通用人脸和指纹素材移除 Mock 及演示用途水印。申请人 ID 按实际关联对象展示。列表缩略图、详情和放大预览使用对应的图像。

申请人列表及详情底部的共享 Mock 数据、图像与本地入库记录绑定等开发说明按全局文案要求移除。

图像的定位与关联复用 ABIS 现有的申请人 ID、模态、指位及图像存储引用。Mock 拼接的图像记录编号仅用于组织测试数据，移除缩略图下方的长编号、放大预览中的「记录 ID」行及辅助文本中的该编号。该编号不作为正式接口或数据库的新增字段要求。

整人重采时，客户先调用人脸和指纹删除接口，再使用同一 `userId` 重新注册。人脸删除生效后，申请人暂时退出列表。新人脸注册成功后重新出现，指纹区域展示本轮已成功入库的指位。例如原有 10 指，删除后本次成功注册 8 指，抽屉只显示本次入库的 8 张指位卡片。列表的十个固定指位中，另外两格显示缺采占位。历史注册、删除请求继续在入库变更记录中追溯。

## 5. 匹配阈值配置

### 5.1 下限校验与默认值

人脸 1:N 查重阈值低于 60，或指纹 1:N 查重阈值低于 40 时，在对应输入框旁提示协议生效下限，并禁用「保存修改」。有改动且两项输入均有效时，可以保存。人脸 60、指纹 40 均为有效值。

将「恢复默认值」改为「填入默认值」，旁边提示「保存后生效」。点击后，人脸和指纹输入值均填为 60。输入值发生变化时标记为未保存。点击「保存修改」并确认后生效。保存时继续显示变更前后的阈值，离开有未保存修改的页面时继续提示。

### 5.2 验收要求

1. 分别输入人脸 59、指纹 39，核对对应输入框旁的提示和保存禁用状态。将输入调回有效范围，核对提示消失，已有修改可保存。
2. 在当前配置与默认值不同时点击「填入默认值」，核对两个输入框均为 60。分别验证放弃修改后仍显示原配置，以及保存并确认后显示新值。

## 7. 账户管理界面

### 7.1 新建账户的选填字段

新建账户时，电话、邮箱和备注默认值为空，输入框以「选填」作为占位提示。每次重新打开新建表单时，恢复为空值。保存时按现有接口约定提交未填写字段，缺失值在列表或详情中显示为「—」。

### 7.2 页面布局

账户管理以主卡片顶部的一处紧凑标题「账户管理」标识页面。移除内容区重复的面包屑、大图标及大标题，将原「控制台账户」卡片标题改为「账户管理」。标题下方排列查询输入框、「查询」和「新建账户」，桌面端查询操作靠左、新建账户靠右。移除顶部账户数量及其占位，结果总数仅在底部分页区显示。
