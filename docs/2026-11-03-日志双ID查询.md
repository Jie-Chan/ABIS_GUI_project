# 日志按申请人和业务请求查询

日志查询新增两个入口，支持运维人员按申请人排查多次调用，或按一次业务请求追查调用和重试。

| 界面名称 | 前端字段 | 语义 |
| --- | --- | --- |
| 申请人 ID | `userId` | 用户确认的业务接口 userId；按字符串处理，保留前导零 |
| 业务请求 ID | `requestId` | 前端暂定字段名，真实接口字段及重试复用规则仍待确认 |

两个输入均去除首尾空白、精确匹配；同时填写时与时间、接口、生物模态、结果、耗时取交集。查询回到第一页，翻页保留条件，重置清空两个 ID。支持回车查询。

列表优先展示两类 ID，调用详情也展示完整 ID；缺失或没有关联 ID 的历史记录显示“—”。CSV 增加两列，沿用同一筛选逻辑，导出全部匹配结果，不局限于当前页。ID 不替代日志记录自身的 `id`，也不自动使用其他链路追踪字段。

桌面筛选区分两行，上方为两个 ID、时间和查询按钮，下方保留原有业务条件；窄屏表格内部横向滚动，操作列不固定，避免遮挡 ID。

## 真实接口后续对接

`LogRecord` 增加可选 `userId/requestId`，`LogQueryParams` 增加同名查询参数。后端需要存储和返回两类标识，并在分页、计数、导出之前执行筛选；不能只过滤当前页。业务请求字段若与 `requestId` 不同，应由真实适配器明确映射。

当前工程的 HTTP 适配器仍为原有未实现骨架，本次不宣称真实日志已支持 ID 查询。
