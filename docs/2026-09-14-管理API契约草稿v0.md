## 1. 通用约定

| 项 | 约定 | 备注 |
| --- | --- | --- |
| 基础路径 | `/abis-admin`（建议） | 管理入口用**独立路径还是独立端口**未定 —— 待澄清第 3 项，部署侧 |

| 错误响应 | **结构未定** | 错误码风格与响应体 —— 待澄清第 5 项。mock 以 `throw new Error('中文文案')` 表达，前端直接展示该文案 |

### 1.1 前端对错误响应的最小期望

前端只需要「**一句可直接示人的中文原因**」。当前 mock 抛出的文案如下，请 ABIS 侧
确认真实错误响应如何映射到这一句：

| 场景 | mock 文案 |
| --- | --- |
| 账户不存在或已禁用 | `账户不存在或已被禁用` |

| 管理 API 未就绪（http 适配器） | `管理 API 契约未冻结…` |

## 2. 数据结构（响应体字段）

字段名**与前端渲染一一对应**，改动字段名会直接改动界面。

### 2.1 `Account` —— 账户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 主键 |
| `username` | string | 登录名，**唯一** |
| `displayName` | string | 姓名（界面「姓名」列） |
| `role` | `'admin'` \| `'operator'` | 角色。界面另经 `ROLE_LABEL` 映射为「管理员」/「运维员」 |
| `enabled` | boolean | 启用 / 禁用。**禁用后不可登录，历史操作记录保留**（需求 1.1） |
| `createdAt` | string | 创建时间，`'YYYY-MM-DD HH:mm:ss'` |
| `lastLoginAt` | string | 最近登录时间；**从未登录时为 `'—'`**（mock 的初值约定，请确认后端沿用） |

### 2.2 `MonitorMetrics` —— 算法服务运行指标

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cdcHealthy` | boolean | |
| `cdcReady` | boolean | |
| `galleryTotalSize` | number | 底库总量 |
| `licenseStatus` | `'VALID'` \| `'INVALID'` | |

### 2.3 `MonitorItem` —— 单个监控对象

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | string | 对象标识 |
| `name` | string | 展示名 |
| `layer` | string | 所属层次 |
| `status` | `'normal'` \| `'abnormal'` \| `'unreachable'` \| `'not_deployed'` | **4 种状态**。⚠ `not_deployed`（未部署）**不计入异常计数** —— 需求 1.3 |
| `instances` | `Array<{id: string, status: string}>` | 实例列表 |
| `optional` | boolean | 是否可选组件 |
| `metrics` | `MonitorMetrics?` | **仅算法服务有** |

> ⚠ **`metrics` 不保证存在**：非算法服务对象上它可能是**缺失的键**，也可能是
> **存在但为 `undefined` 的键**（取决于适配器是否经过序列化边界）。
> 消费方一律按真值判断（`if (item.metrics)`），**不得使用 `'metrics' in item`**。

### 2.4 `LogRecord` —— 调用日志

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | |
| `calledAt` | string | 调用时间 |
| `caller` | string | 调用方标识 |
| `api` | string | 接口 key（见 §3.12 的枚举） |
| `apiLabel` | string | 接口中文名（**后端直接给中文**） |
| `feature` | `'face'` \| `'finger'` | 生物模态 |
| `result` | `'success'` \| `'failure'` | 结果状态（**英文枚举**） |
| `costMs` | number | 处理耗时，毫秒 |

### 2.5 `AuditRecord` —— 审计记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | |
| `operatedAt` | string | 时间 |
| `operator` | string | 操作人 |
| `role` | `'admin'` \| `'operator'` | 角色 |
| `roleLabel` | string | 角色中文名（**后端直接给中文**） |
| `action` | string | 操作类型 |
| `target` | string | 操作对象 |
| `beforeValue` | string | 变更前值。**非变更类操作为空串**（界面渲染为 `—`） |
| `afterValue` | string | 变更后值。同上 |
| `result` | string | 结果。⚠ **这里是中文 `'成功'` / `'失败'`**，与 `LogRecord.result` 的英文枚举**不是同一套** |
| `sourceIp` | string | 来源 IP。⚠ 依赖 `X-Forwarded-For` 透传 —— 待澄清第 15 项 |
| `sessionId` | string | 会话 ID |

## 3. 接口清单（15 个方法）

下表按 `src/api/contract.js` 的 `API_METHODS` 顺序。前 11 行对应《设计方案》§8 的 11 行端点表
（§8 的 11 行又对应需求附录 A.1 的 8 条能力，是同一能力落到端点粒度）。

### 3.1 `login` — 登录

- **建议端点**：`POST /abis-admin/auth/login`（§8 第 1 行）
- **需求出处**：1.1
- **请求**：`{ username: string, password: string }`
- **响应**：`{ token: string, account: Account }`
- **错误**：
  1. 账户不存在**或已被禁用** → `账户不存在或已被禁用`
  2. 用户名存在但口令不符 → `用户名或密码错误`

> ⚠ **校验顺序是有意的**：**先判禁用、再判口令**。若反过来，被禁用账户输入错误口令会得到
> 「用户名或密码错误」，用户会以为自己记错了密码。请 ABIS 侧确认沿用此顺序与文案。
>
> 🔒 口令以**加盐哈希**存储 —— **属 ABIS 侧实现要求，前端不接触**（需求 1.1）。
> 前端**不构成安全边界**，授权须在 ABIS 侧强制校验。

### 3.2 `logout` — 登出

- **建议端点**：`POST /abis-admin/auth/logout`（§8 第 2 行）
- **需求出处**：1.1
- **请求**：无
- **响应**：无（`void`）

### 3.3 `getSession` — 会话校验

- **建议端点**：`GET /abis-admin/auth/session`（§8 第 3 行）
- **需求出处**：1.1
- **请求**：无
- **响应**：`{ account: Account }` 或 `null`

> ⚠ **本条是当前骨架的一处已知缺口**：`contract.js` 的签名**允许返回账户**，
> 但 mock 实现**恒返回 `null`** ⇒ **刷新页面即丢登录态**（收尾发现 A7）。
> 会话空闲超时时长未定 —— 待澄清第 12 项。

### 3.4 `listAccounts` — 账户列表

- **建议端点**：`GET /abis-admin/accounts`（§8 第 4 行）
- **需求出处**：1.1
- **请求**：`{ page?: number, pageSize?: number, keyword?: string }`
  - `keyword` 同时匹配 `username` 与 `displayName`（**模糊包含，非前缀**）
- **响应**：`{ total: number, items: Account[] }`

### 3.5 `createAccount` — 创建账户

- **建议端点**：`POST /abis-admin/accounts`（§8 第 4 行）
- **需求出处**：1.1
- **请求**：`{ username: string, displayName: string, role: 'admin'|'operator' }`
- **响应**：`Account`（**含服务端生成的 `id` / `createdAt`**）

> mock 的服务端赋值约定：`enabled = true`（新建即启用）、
> `createdAt = 当前时间`、`lastLoginAt = '—'`。请确认后端一并返回完整 `Account`，
> 而非仅返回 `id` —— 前端当前直接用返回对象刷新列表。

### 3.6 `updateAccount` — 账户修改 / 禁用 / 启用

- **建议端点**：`PUT /abis-admin/accounts/{id}`（§8 第 5 行）
- **需求出处**：1.1
- **请求**：`Partial<Account>` —— 实际用到三种形态：
  - 编辑：`{ displayName, role }`
  - 禁用 / 启用：`{ enabled: boolean }`
- **响应**：`Account`（更新后的完整对象）
- **错误**：`id` 不存在 → `账户不存在`

> ⚠ **`id` 不存在必须报错，不得静默返回空对象**。若静默返回 `{}`，页面会显示「保存成功」，
> 而写得其实是一次不存在的更新，且返回的空对象会把该行**渲染成空白** ——
> 只有真实后端会拒绝时才发现。mock 已按此报错。
>
> ❓ **同时是待澄清第 A11 项**：ABIS 是否拒绝「**停用自己**」与「**停用最后一个管理员**」？
> 需求文档对此**完全沉默**。答案决定的是**契约**（ABIS 要不要拒绝），不是界面 ——
> 若拒绝，前端只需把拒绝原因原样呈现（现有实现已如此）；若不拒绝，这是一条**能把自己锁在
> 系统外、且没有第二个管理员可救**的路径，需产品侧显式接受。

### 3.7 `deleteAccount` — 删除账户

- **建议端点**：`DELETE /abis-admin/accounts/{id}`（§8 第 5 行）
- **需求出处**：1.1
- **请求**：无
- **响应**：无（`void`）

> ❓ **删除后其历史审计记录的操作人如何存续** —— 待澄清第 13 项。
> 界面已注明「所有账户操作均记入审计，审计记录只读」。

### 3.8 `resetPassword` — 密码重置

- **建议端点**：`POST /abis-admin/accounts/{id}/password-reset`（§8 第 6 行）
- **需求出处**：1.1
- **请求**：mock 当前传 `{}`（**空对象**）
- **响应**：无（`void`）
- **错误**：`id` 不存在 → `账户不存在`

> ❓ **请 ABIS 侧确认**：重置后的新口令是**服务端生成并展示一次**、
> 还是**由管理员在请求里传入**、还是**走邮件 / 短信**？
> 当前前端只调用接口并提示「密码已重置」，**没有任何输入新口令的界面**。
> 契约签名 `(id: number) => Promise<void>` 是「无入参、无返回」，请确认是否成立。

### 3.9 `getThresholds` — 阈值读取

- **建议端点**：`GET /abis-admin/thresholds`（§8 第 7 行）
- **需求出处**：1.2
- **请求**：无
- **响应**：`{ face: number, finger: number }`

> ⚠ **键名是 `face` / `finger`，不是 `fingerprint`**。本项目有**三套并存的键空间**，
> 混用不会报错、只会静默写错：**监控词汇**用 `'fingerprint'`、**生物模态 / 阈值词汇**用
> `'finger'`。请 ABIS 侧明确各接口分别属于哪一套。
>
> 仅两类阈值：人脸 1:N 去重、指纹 1:N 去重。**不含 Top-N，不含 1:1 核验判定阈值**
> （后者归 SIGATT 业务系统）。

### 3.10 `updateThresholds` — 阈值写入

- **建议端点**：`PUT /abis-admin/thresholds`（§8 第 7 行）
- **需求出处**：1.2
- **请求**：`{ face?: number, finger?: number }`
- **响应**：写入后的完整 `{ face: number, finger: number }`
- **错误**：请求含**非法键** → `阈值键不合法：{键名}（合法键：face、finger）`

> ⚠ **阈值是两个键的封闭空间，不是开放的任意字段袋**。无条件 merge 会让
> `updateThresholds({ fingerprint: 90 })` **静默写出第三个键**，而真实 ABIS 会以
> 「传入的阈值不合法」拒绝 —— **mock 必须同样报错**，否则调用方的键名笔误在联调前
> 永远暴露不出来。请 ABIS 侧确认这一拒绝行为与错误码。
>
> **取值范围 1–100 的整数**（上限 100 为产品设定值）。变更须记录操作人、时间、
> 变更前后值并纳入审计（需求 1.2）。
>
> ❓ **协议生效下限（人脸 60 / 指纹 40）的取得方式** —— 待澄清第 10 项；
> **下限的处置语义（纠正 / 拒绝）** —— 待澄清第 11 项。
> 前端已把两种语义的文案都备好，由单点常量切换，**未二选一**。

### 3.11 `getHealth` — 聚合健康查询

- **建议端点**：`GET /abis-admin/health`（§8 第 8 行）
- **需求出处**：1.3
- **请求**：无
- **响应**：`{ items: MonitorItem[], fetchedAt: string }`

> 需求 1.3 已确认在 ABIS 侧**新增一个聚合健康接口**，由该接口采集全部监控对象，
> **前端仅调用此单一接口、不直连任何内部节点**。
>
> - 初版只需输出各监控对象的健康状态 + 算法服务运行指标；
> - **不要求**输出集群主备归属与实例拓扑（需求 B.3）；
> - **不要求**覆盖 Nginx / Keepalived / Patroni / etcd / HAProxy（需求 B.4）；
> - ❓ **监控实例粒度（2 还是 4）** —— 待澄清第 8 项，决定监控页渲染行数；
>   ❓ **「未部署」态的判定来源** —— 待澄清第 9 项，决定本接口实现。
>
> 前端当前每 **60 秒**轮询一次本接口（另有「立即刷新」按钮触发即时刷新）。

## 4. 导出接口的文件约定

两个导出接口返回的**不是 JSON**，是 CSV 文件流。前端当前按以下结构解析 / 生成：

| 项 | 约定 |
| --- | --- |
| MIME | `text/csv;charset=utf-8` |
| BOM | **带 UTF-8 BOM（`﻿`）** —— 不加则 Excel 打开中文乱码 |
| 表头 | 中文，**不加引号** |
| 正文单元格 | **引号包裹 + `"` → `""` 转义** |
| 行分隔 | `\n` |
| 文件名 | `abis_api_logs_YYYYMMDD_HHmmss.csv` / `abis_audit_YYYYMMDD_HHmmss.csv`（前端生成） |

### 4.1 日志 CSV 列（6 列）

```
调用时间, 调用方标识, 接口, 生物模态, 结果状态, 处理耗时(ms)
```

⚠ 记录里 `feature` / `result` 存的是**英文枚举 key**，落表时**必须转中文**
（`face` → `人脸`，`success` → `成功`），否则会在中文表头下写出英文值。

### 4.2 审计 CSV 列（10 列）

```
时间, 操作人, 角色, 操作类型, 操作对象, 变更前值, 变更后值, 结果, 来源 IP, 会话 ID
```

审计记录直接使用 `roleLabel`（后端已给中文），与日志的映射方式不同。

### 4.3 一条硬约束：**不得含生物图像数据**

**导出内容与 mock 数据均不得包含任何生物图像数据**（base64 人脸 / 指纹图像）——
需求 1.4 明确禁止。本骨架已实测：导出的 CSV 中**不含** `data:image`、JPEG / PNG 魔数、
base64 特征串 —— 这是与长度无关的判据。长度旁证（**字符与 UTF-8 字节是两把尺子，
最长单元格不必然是同一个**）：按**字符**计 logs 最长 **32 字符**、audit 最长 **19 字符**；
按 UTF-8 **字节**计 logs 最长 **40 字节**、audit 最长 **23 字节**
（中文 / 全角字符各占 3 字节，故字节数大于字符数）—— 与任何图像载荷的量级相差数个数量级。

### 4.4 界面上一个已知的两义性（非缺陷）

表头行不加引号、正文却加，是**不对称**的。当前表头文案全是中文且不含 `,` / `"`，
**所以现在是潜伏的**；将来出现含 `,` 或 `"` 的表头文案会**静默错列**（收尾发现 A4）。

## 5. ⚠ 时间参数的硬约束（最容易被忽视的一条）

`startTime` / `endTime` 与记录里的 `calledAt` / `operatedAt` 之间是**字符串比较**，
**三者同为 `'YYYY-MM-DD HH:mm:ss'` 才成立**。

**传 Date 对象或 `'YYYY-MM-DD'` 不会报错，只会静默返回空列表。**

前端页面从 `el-date-picker` 拿到的是 `Date` 对象，**必须先经 `formatDateTime` 归一化再传入**。
请 ABIS 侧确认后端**同样按字符串比较**，或明确改为时间戳 / 各自解析 ——
**这条若两边理解不一致，症状是「查询永远返回空」，且没有任何报错。**
