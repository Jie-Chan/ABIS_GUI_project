# 申请人重采与变更日志联动

依据：[20261112 开发文档](<20261112-ABIS mock界面开发文档.md>) 18:05 版。本轮保留原有 15 条默认日志、图像比对，以及此前申请人 ID 筛选项加宽至 260px 的未提交修改；没有执行 Git commit。

日志筛选使用三列共用网格。第一行为请求 ID、用户 ID、时间范围；第二行为接口类型、生物模态、执行状态，查询/重置在最右侧。每列的上下标签和控件起点对齐。移除总耗时筛选，列表继续展示请求耗时，筛选和导出仍按同一请求集合执行。

申请人以当前有效人脸记录作为入表条件，指纹允许缺采。列表仅显示申请人 ID、首次入库时间、最近入库变更时间、查看详情；移除模态筛选、入库数量列和列表级日志操作。默认共有 7 名有效人脸申请人：U001、U004、U006、U010、U201、U202、U203。指纹专属对象不进入列表，但共享图像记录仍保留，查重图像功能可继续读取。

详情默认显示“当前入库图像”，保留人脸和左右手指位、缩略图放大、图像不可用及未入库状态。“入库变更记录”展示已生效的注册/删除、模态、生效时间及指位数，每条通过“查看日志”跳转。只有有明确记录的业务变更才展示；原有预置人员没有登记到日志中的历史操作不编造变更记录。

默认 U001 人脸注册关联 REQ-00000001＋REQ-00000003，指纹注册关联 REQ-00000002＋REQ-00000004。关联关系在共享业务记录中明确保存，未按同一用户相邻时间推断。日志查询按 userId 与 requestIds 集合取交集，CSV 同样限定；可切换为该用户的常规日志查询。返回恢复申请人查询、页码、排序、列表位置、抽屉标签和抽屉滚动位置。

## 独立重采测试数据

`src/mock/recapture.js` 的 `buildRecaptureLogs()` 提供 U900 的原有人脸/10 指注册、关联查重、人脸删除、指纹删除、新人脸注册、关联查重、新 9 指注册和后续查重。`fingerFailure: true` 将本轮指纹注册改为明确失败。该组数据不添加到默认列表，浏览器专项在当前测试会话中临时使用它。

重放共享记录得到：人脸删除后申请人退出列表；删除指纹后清除全部旧指纹；新脸成功后恢复入表且首次入库时间仍为最早的人脸成功时间；本轮指纹成功后只展示新 9 指，右手小指未入库。本轮指纹失败时新人脸保留、无旧指纹回流、失败不计入已生效变更，最近变更时间停留在人脸注册成功时。

对有关联查重的注册、无关联查重的注册、人脸删除及指纹删除分别验证日志结果为“注册＋查重”“仅注册”“仅本次人脸删除”“仅本次指纹删除”，不会混入同一用户其他轮次。

修改主要涉及共享入库快照计算、申请人 API/列表/详情及 Pinia 返回上下文、日志请求集合过滤与路由、筛选网格和独立验收数据。真实接口仍待后端对接，全部图像与报文为本地 Mock。
