# 监控二态、阈值重置与页面精简

本轮在 main `352af69` 上继续修改，保留此前尚未提交的新密码长度提示。以用户最新要求为准：监控页去掉授权状态和底库容量，暂不增加全局授权栏；阈值重置保存 60/60；服务仅展示正常、异常。不提交或推送 Git。

## 去掉授权状态和底库容量

- 服务卡片移除授权状态、底库规模/容量及对应分隔区域；不添加示意图中的全局授权栏。卡片保留名称、层级、实例数量、服务和实例的运行状态。
- 删除容量格式化、授权状态转换、算法指标样式和未使用的指标常量；删除本轮临时添加的 checks 容量提取映射。
- 管理 API 的监控适配器继续校验原始对象状态及实例数组后透传快照，不再派生授权或容量字段。后端返回的 metrics/checks 可以保留，当前页面不读取和展示这些内容。
- 前一阶段的授权字段选择问题随本次取消展示一并结束，无待确认项。后续需要时再按全系统统一授权和容量的设计重新对接。

## 阈值重置

- 重置通过已有 `PUT /admin-api/abis/thresholds` 保存 `{ "face": 60, "finger": 60 }`，不再只是重新读取配置。
- 仍需二次确认，显示原来生效值到 60 的变化；取消不请求、不改变未保存输入。
- 与保存共用写入和回读流程。布尔成功后 GET 回读，取得权威结果后才更新表单和显示成功；写入失败保留原输入，写入成功但回读失败明确提示已经写入，避免误报未写入。
- 确认和保存期间锁定控件，避免重复操作。管理员和运维员沿用现有阈值权限。
- 重置默认值是 60/60；没有改变既有协议下限和普通保存校验。

## 服务二态

保留后端枚举以兼容现有快照校验；视图将 `normal` 显示为“正常”，`abnormal/unreachable/not_deployed` 统一为“异常”，实例同样归并，未知实例状态也不显示为正常。全量统计调整为对象总数、正常、异常，异常筛选包含未部署对象，不再出现“不可达”“未部署”的状态标签或分类说明。

读取失败、旧数据、首次加载及无效响应的诊断仍保留；它们是数据获取提示，不将无效快照填充成正常状态。路由、账户权限、身份恢复、代理和 60 秒轮询均沿用现有流程。
