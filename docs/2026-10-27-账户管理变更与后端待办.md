## 2. 账户资料字段

新建和编辑表单均展示：

| 字段 | 中文名称 | 要求 |
| --- | --- | --- |
| `username` | 用户名 | 必填；编辑时只读 |
| `displayName` | 姓名 | 必填 |
| `role` | 角色 | 必填；`admin` / `operator` |
| `phone` | 电话 | 选填；默认 `"-"` |
| `email` | 邮箱 | 选填；默认 `"-"`；填写其他内容时校验邮箱格式 |
| `remark` | 备注 | 选填；默认 `"-"`，多行文本 |

可选字段缺失、null、空字符串或仅空白时，前端归一为字符串 `"-"`；非空字符串去除首尾空白。此处短横线是 ASCII `-`，与账户时间缺失的 `—` 不同。

新建请求：

```http
POST /admin-api/system/user
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "username": "ops.example",
  "displayName": "示例运维员",
  "role": "operator",
  "phone": "-",
  "email": "-",
  "remark": "-"
}
```

编辑请求使用 `PUT /admin-api/system/user/{id}`，提交姓名和三项可选资料；仅编辑其他运维员时携带所选角色，编辑本人或任意管理员时省略 `role`。不提交用户名、密码或 UI 内部字段。允许的启停操作仍只发送 `{ "enabled": true/false }`，不会覆盖其他资料。创建和编辑后重新读取后端列表，不把填写值缓存为虚构记录。

## 3. 右上角账户菜单与个人信息

头像/用户名整体可点击，也支持键盘展开，菜单仅含：

- 个人信息
- 退出登录（保留原二次确认、注销请求、失败时本地清理流程）

原顶部独立“退出登录”按钮已移除。个人信息弹窗展示账户 ID、用户名、姓名、角色、电话、邮箱和备注；打开时通过既有 `GET /admin-api/system/auth/get-permission-info` 刷新当前身份。没有新造个人信息查询路由。

改密表单始终保留原密码、新密码、确认新密码及“保存新密码”。前端检查必填、新旧密码不同、两次新密码一致；服务端必须自行校验原密码、密码策略和当前会话。确认密码和目标 ID 不发送到后端。

```http
POST /admin-api/system/auth/change-password
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "oldPassword": "<原密码>",
  "newPassword": "<新密码>"
}
```

期望成功响应：

```json
{
  "code": 0,
  "data": { "reauthenticationRequired": true },
  "msg": ""
}
```

成功后前端清除标签页会话和密码输入，关闭弹窗并跳回登录页。关闭弹窗或组件卸载同样清除密码，不写入 localStorage、sessionStorage 或个人资料。错误原密码、服务失败及接口缺失均保留失败状态，不退出有效会话、不显示成功；401 仍走已有会话失效处理。

当前接口缺失时按钮仍保留。HTTP 404/405/501 会显示“服务暂未提供修改密码功能，请联系系统管理员”。
