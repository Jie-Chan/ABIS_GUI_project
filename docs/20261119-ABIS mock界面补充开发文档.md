# ABIS Mock 补充开发｜主机映射与五档历史趋势

## 1. 本次交付

在现有前端 Mock 工程中完成两项开发：

1. **把测试 Hub 和主机映射改为工程配置。** 由 Mock 工程内提供同源接口的服务端代码读取配置、登录 Hub 并查询数据。实际配置只登记应用服务器 01（121）。
2. **给主机详情增加一个时间选择器。** 默认「近 1 小时」，另有「近 12 小时」「近 24 小时」「近 7 天」「近 30 天」。四张资源图共用一个选择器。

开发和联调都在现有 Mock 工程中完成。正式 ABIS GUI 后端、原生「实时 1 分钟」订阅和服务状态页不在本轮范围内。上一版的字段、触屏点选与断采规则见 [[20261118-ABIS mock界面补充开发文档]]。

## 2. 在 Mock 工程内配置 121

交付一个可由 Mock 服务启动时直接读取的配置文件。建议使用 `config/beszel.json`；若已有服务端配置目录，沿用其路径。以下为本轮完整的 Hub 和主机映射示例：

```json
{
  "hub": {
    "baseUrl": "http://10.200.51.121:8090",
    "usernameEnv": "BESZEL_USERNAME",
    "passwordEnv": "BESZEL_PASSWORD"
  },
  "hosts": [
    {
      "hostId": "app-1",
      "systemId": "vgrg02yzsr69lc7"
    }
  ]
}
```

- `hostId` 对应 ABIS 名录中的「应用服务器 01（121）」，`systemId` 对应该 Hub 中名为 `121` 的系统记录。通过这对 ID 关联。主机显示名称和 IP 沿用现有主机资料。
- 环境变量名为示例，已有变量可复用。真实账号、密码由开发服务器在启动 Mock 时注入，使用可读取 121 的 Hub 账号。示例文件中只写变量名。配置由服务端加载，避免放入 `public/`、使用 `VITE_*` 保存凭据或从 Vue 组件导入配置。
- 在 Mock 工程的运行说明里注明实际配置路径、两个环境变量的名称，以及修改配置后如何重新加载。后续接入已有名录中的其他主机时，在 Hub 授予同一账号访问权，再添加对应映射即可。
- 界面继续列出 2 台应用服务器、2 台算法 VM、3 台 PostgreSQL VM 和 1 台 MinIO VM。接入状态由映射决定。其余 7 台本次均显示「未接入」，指标为 `—`，无展开按钮，也不产生 Hub 查询。已映射的 121 读取失败时显示原有重试状态。

## 3. 五档数据怎么取

扩展现有同源接口 `GET /abis-admin/monitor/hosts`，增加可选参数 `range`。例如 `GET /abis-admin/monitor/hosts?range=1w` 返回近 7 天趋势。省略参数沿用现有近 1 小时行为。服务端只接受下表五个值，使用已配置的系统 ID 查询 Hub 的 `system_stats` 集合。

| 界面选项 | ABIS 参数 `range` | Beszel 记录 `type` | 相邻点预期间隔 |
| --- | --- | --- | --- |
| 近 1 小时（默认） | `1h` | `1m` | 1 分钟 |
| 近 12 小时 | `12h` | `10m` | 10 分钟 |
| 近 24 小时 | `24h` | `20m` | 20 分钟 |
| 近 7 天 | `1w` | `120m` | 2 小时 |
| 近 30 天 | `30d` | `480m` | 8 小时 |

表中 `type=1m` 表示每分钟一条的历史记录。所有五档都走历史查询。按系统 ID、记录类型和所选 UTC 时间窗过滤，按 `created` 升序返回。Hub 实际保存了多少个点就展示多少个点，尤其要覆盖 121 接入时间不足 7 天、30 天的情况。[Beszel v0.21.2 时间范围定义](https://github.com/henrygd/beszel/blob/v0.21.2/internal/site/src/lib/utils.ts#L119-L168)

**接口要分清“主机现在怎样”和“所选时段怎样”。** 沿用 `items[]` 和已有指标字段，各档按以下约定返回：

| 数据 | 含义 | 界面用途 |
| --- | --- | --- |
| `item.sample` | 已映射主机最新可用的分钟样本，沿用现有近一小时查询口径 | 收起行、四张卡顶部的当前读数、「采集于」及 120 秒断采判断 |
| `item.history[]` | 所选时间窗、所选粒度的历史点 | 曲线、面积填充以及鼠标或触屏选中点的明细 |

在 `1h` 档可从同一批分钟记录取得两者。其余档单独取得最新分钟样本，趋势取对应汇总记录。例如 30 天图最后一个点距今数小时是正常情况，不能据此将 121 标成断采，也不能以当时的汇总值覆盖当前 CPU 使用率。沿用已有采样转换，包括 CPU 分项、内存缓存、Swap、磁盘延迟及网络收发。每个提示框读取被选中历史点自身的值和时间。

## 4. 页面交互及改动入口

- **选择器位置。** 从「监控 → 主机资源」展开 121，在四图上方同一行左侧放「采集于」，右侧放一个紧凑的下拉选择器。手机宽度下也只出现一个选择器。主机收起后隐藏该行。
- **切档。** 一次选择同时更新 CPU、内存、磁盘、网络的时间窗、横轴和提示时间。跨天横轴应看得出日期。磁盘已选「延迟」时，换档后继续显示延迟。轮询和错误重试沿用当前档位。
- **数据稀疏和空窗。** 横轴覆盖完整所选时段，接入前留白。断线阈值按所选粒度计算，可沿用现有的“预期间隔 × 1.5”规则。缺口处曲线和填充同时断开，孤立的有效点仍可查看，真实零值保留。新选档位没有历史时显示「该时段暂无数据」，概览继续使用有效分钟样本。
- **快照与切换顺序。** 快速从 30 天切回 1 小时，只允许最新选择对应的响应更新图表。请求失败时，可保留同一主机、同一档位的有效趋势；尚无该档快照时显示错误及重试。沿用既有每 60 秒一组轮询和分钟数据断采保留规则。切档时清除上一档的采样点提示。
- **代码入口。** 在提供 `/abis-admin/monitor/hosts` 的 Mock 服务端处理器读取配置并转换查询。在 `src/api/adapters/mock.js` 传递档位，调整只接受一个 `app-1` 的响应校验。在 `src/views/HostResourcesView.vue` 将接入、快照与选中主机按 ID 关联，去除前端的单机绑定。在 `src/constants/hostResources.js` 和 `src/components/HostMetricChart.vue` 中，把固定一小时时间轴、固定 90 秒断线阈值及“近一小时”图表标签改为随档位更新。
