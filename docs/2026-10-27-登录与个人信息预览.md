# 登录页与个人账户菜单

本轮在 `front-end` 分支按已审阅的两张静态示意图实现，使用现有 Vue 3、Element Plus 和 Pinia。预览入口仍为 `http://10.200.51.121:5186/login`，启动使用 `npm run dev:mock -- --host 0.0.0.0`。

## 登录页

保留居中、无外围卡片的登录表单，增加浅蓝背景层次、淡网格、指纹轮廓、人脸几何线稿及服务连接节点。装饰通过独立 SVG 组件实现，不使用整页截图作为背景。小屏收起两侧线稿，保留表单空间。

ABIS 品牌层级、输入框与主按钮样式已调整，演示账户收拢为独立提示区。Mock 数据来源提示、演示凭据、登录校验、接口调用与跳转处理保持原有行为。

## 个人账户

右上角头像及用户名是账户菜单入口，支持点击和键盘展开，包含「个人信息」「退出登录」两项。原独立退出按钮移除，退出仍使用原来的二次确认、注销和登录页跳转流程。

个人信息弹窗只读展示当前登录账户的 ID、用户名和角色，不依赖账户列表权限，管理员和运维员均可打开。弹窗中的本人改密填写原密码、新密码和确认新密码；校验必填及两次输入一致，只向接口发送原密码和新密码，不发送目标账户 ID 或确认密码。关闭弹窗清空密码和错误；保存期间阻止重复提交。成功后清除本地登录态并返回登录页。

## 接口边界

在 `src/api/contract.js` 中新增 `changePassword({ oldPassword, newPassword })`，由当前会话确定本人身份。Mock 适配器校验会话、账户状态和原密码，仅更新内存中的本人凭据；模块重新加载后恢复种子演示密码。密码不写入 localStorage/sessionStorage，不回传到个人信息展示对象。

HTTP 适配器提供明确的未实现错误，尚未实现真实后端本人改密。后续集成 main 时应按实际接口补齐该方法和后端密码策略，不能调用账户管理的重置密码接口替代本人改密。

现有登录与退出签名、账户列表重置密码、store 对外契约和角色权限矩阵均保留。此轮不修改 main 目录。

## 检查

工程根目录执行 `npm run build:mock`，在 `frontend-toolkit/verification/` 中执行 `npm test`。测试先确认 Mock 模式，再运行原有界面检查及新增个人账户专项；账户写入仅发生在测试浏览器内的 Mock 模块会话。

专项覆盖原密码错误、确认密码不一致、密码清空、重复提交、旧密码失效及新密码登录、运维员改密与权限隔离、320/390/768px 弹窗布局，以及浏览器报错和真实后端请求检查。
