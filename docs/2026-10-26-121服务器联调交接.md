## 二、当前工程进展

工程是 Vue 3、Vite、Element Plus、Pinia、Vue Router 的 JavaScript 静态 SPA，自身没有后端服务。已有登录、监控、阈值配置、账户管理、调用日志、审计查询 6 个页面。

此前按 Apifox 文档做了接口对照，文档共有 12 个 HTTP 入口，其中 11 个属于管理能力，另一个是业务侧人脸注册。当前已按这些路径实现混合适配器，但受网络影响，尚未获得真实服务响应，也未完成端到端联调。

### 2.1 已实现的真实调用

基础路径为 `/admin-api`，下表路径相对此基础路径：

| 能力 | 方法与路径 | 当前实现 |
| --- | --- | --- |
| 登录 | `POST /system/auth/login` | 提交用户名和密码；读取 `data.accessToken` 或 `data.token`。 |
| 注销 | `POST /system/auth/logout` | 携带 Bearer Token；失败时也清理本地状态，并提示服务端注销未确认。 |
| 监控 | `GET /abis/monitor/snapshot` | 读取监控对象、状态、实例、指标及刷新时间。 |
| 阈值读取 | `GET /abis/thresholds` | 读取 `face/finger` 两项数值。 |
| 阈值保存 | `PUT /abis/thresholds` | 写入两项配置；只返回成功布尔值时，追加一次读取取得保存结果。 |
| 账户创建 | `POST /system/user` | 发送 `username/displayName/role`；不发送 UI 内部字段。 |
| 账户修改与启停 | `PUT /system/user/{id}` | 对具备后端真实 ID 的本次创建记录调用。 |
| 账户删除 | `DELETE /system/user/{id}` | 同上，不使用文档里固定的示例 ID `10`。 |
| 密码重置 | `POST /system/user/{id}/reset-password` | 同上，密码交付方式仍待确认。 |
| 调用日志 | `GET /abis/call-log/page` | 发送页面全部非空筛选条件，保留耗时为 0 的边界。 |
| 审计查询 | `GET /system/audit-log/page` | 发送页面全部非空筛选条件。 |

`live.js` 负责 axios、超时、凭据与认证失效处理；`remote.js` 负责路径、解包和报文转换；`hybrid.js` 负责缺失能力的 mock 接线和账户来源隔离。

目前支持 `{code,data,msg}` 包装，暂以 `code=0` 为成功，`data=false` 为失败。列表支持 `items/list/records + total`。这些是待真实报文核验的实现约定，不能据此推断后端实际结构已经一致。

### 2.2 保留的 mock 和临时处理

| 功能 | 当前处理与限制 |
| --- | --- |
| 账户列表 | 文档未列真实列表接口，沿用 mock 列表并加入本次真实创建的本地记录。它不代表服务器完整账户列表。 |
| 演示账户编辑、启停、删除、重置密码 | 全部走 mock。不能把演示 ID 传给真实写接口。 |
| 本次真实创建账户 | 返回真实 ID 后才可执行真实后续操作；未返回 ID 则禁用该行操作。本地记录刷新后消失，后端账户仍可能存在。 |
| 日志与审计导出 | 导出独立 mock 样本，按钮及文件名标明 Mock，不是当前真实筛选结果。 |
| 会话恢复 | 缺少当前用户/会话校验接口，刷新需重新登录。混合 Token 暂存 `sessionStorage`，尚未实现恢复或完整续期。 |
| 身份角色 | 优先取登录返回的账户角色；无法识别为 `admin/operator` 时标记“角色待后端提供”，临时开放预览导航。后端必须执行真实权限校验；此逻辑不属于正式权限方案。 |

所有页面有混合预览来源说明。真实请求失败或结构不符会报错，不自动切换成 mock 成功。不要用伪造的指标、角色或成功返回掩盖真实问题。

## 四、在 121 上启动

先确认工程包含 `src/api/adapters/hybrid.js`、`.env.hybrid` 和本文。检查 `node -v`、`npm -v`、`command -v node`、`command -v npm`，然后：

```bash
npm ci
node --test tests/hybrid.test.js
npm run build:hybrid
```

先对现有管理服务做非写入检查：

```bash
ss -ltnp 'sport = :7002'
curl --noproxy '*' -v --connect-timeout 5 --max-time 10 \
  http://10.200.51.121:7002/admin-api/abis/thresholds
```

未携带凭据时可能返回 401/403 或业务未认证响应，说明 HTTP 可达，但不代表功能通过。若返回 404，应继续核对基础路径；如果连接失败，检查实际服务地址、监听和运行情况，不先修改前端账号逻辑，也不擅自重启后端服务。

`.env.hybrid` 当前设置：

```dotenv
VITE_API_MODE=hybrid
VITE_API_BASE_URL=/admin-api
ABIS_PROXY_TARGET=http://10.200.51.121:7002
```

如后端经检查可用的是其他地址，在本机 `.env.hybrid.local` 覆盖 `ABIS_PROXY_TARGET`；不要未经检查改成 `127.0.0.1`，服务可能位于容器或只绑定某个地址。

启动联调页面，使用一个确认未被占用的端口，例如 5174：

```bash
npm run dev:hybrid -- --host 0.0.0.0 --port 5174 --strictPort
```

从开发机浏览器访问 `http://10.200.51.121:5174/`，使用真实测试账户登录。若服务器本机能打开而开发机不能，需要检查 5174 的网络访问权限；只报告所需配置，不擅自改服务器防火墙。也可按现有运维方式使用 SSH 端口转发。

请求链路为“浏览器 → 121 上的 Vite → `/admin-api` 代理 → 后端 7002”。浏览器请求相对路径，后端地址由 Vite 在服务器侧连接。

**模式不要选错：** `npm run dev` 是原 mock 演示；只改 `VITE_USE_MOCK=false` 会进入旧 `http.js` 占位适配器。此次联调用 `npm run dev:hybrid`。静态构建可用 `build:hybrid`，但正式静态托管必须单独配置 `/admin-api` 反向代理，Vite 开发代理不会被打包进去。
