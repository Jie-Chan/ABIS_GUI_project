## 本轮功能

- 请求详情和申请人详情共用标题区间距，标题区域下缘至首块信息表格统一为 18 px。同步请求、异步请求及申请人两个标签使用同一规则。
- 图像比对将标题与指位、候选响应信息分别排列，两侧共享标题区的行高。候选信息换行时，两侧图框一起下移；默认三候选切换时，标题和图框保持原位置，待查图像持续显示。
- 申请人图像预览居中，最大高度随当前视口调整，上下各保留至少 16 px。人脸和指纹完整等比显示；空间不足时内容区滚动，标题、关闭图标及底部关闭按钮保持可用。调整窗口高度时自动重新分配空间。
- 审计操作人输入框按 Enter 执行与「查询」相同的动作，回到第一页，列表、总数及全部分页 CSV 同步使用本次条件。申请人、日志的 ID 回车查询继续可用。
- 新建账户的电话、邮箱、备注初始为空，显示「选填」占位；取消后重新打开恢复空值。编辑缺失值时也使用空输入，详情统一显示「—」。提交仍沿用当前接口以 `-` 表示空值的约定，已填写内容正常保存。
- 账户管理只保留卡片顶部一处「账户管理」标题。查询靠左，新建账户在桌面靠右；总数只在底部分页显示。长列表在固定表头与分页之间独立滚动，少量和空结果自然收缩，窄屏保留横向表格操作。

## 后续修复：HTTP 服务器地址的账户密码生成

使用普通 HTTP 的服务器 IP 地址复现了 `crypto.randomUUID is not a function`。该访问环境的 `isSecureContext` 为 `false`，没有 `randomUUID`，但支持 `getRandomValues`。原创建流程先保存账户再生成初始密码，生成异常导致页面报错、账户已存在且没有可用密码。前一轮本机地址验证未覆盖这一差异。

`src/api/adapters/mock.js` 改为使用 `crypto.getRandomValues`，新建和重置密码共用此方法；创建时先生成密码，成功后才写入账户并递增 ID。密码生成失败不会留下已启用账户或占用用户名，同名可以直接重试。已有启用账户即使缺少登录凭据，也可通过「更多 → 重置密码」取得可用的新密码。

新增 `frontend-toolkit/verification/review-account-http.mjs`，普通 HTTP 服务器 IP 与本机地址各执行 13 项，共 **26 项检查通过**；每种地址都覆盖原生浏览器和显式禁用 `randomUUID`。验证选填全部留空及有效电话、邮箱两种创建、初始密码展示和实际登录、重置后旧密码失效、缺少原始凭据的恢复、生成异常无残留与同名重试，以及重置失败保留原密码。构建通过，浏览器错误和真实后端调用均为 0。

在 `frontend-toolkit/verification` 使用 `ABIS_PREVIEW_URL=http://服务器IP:5186 npm run test:account-http` 可复核实际 HTTP 访问场景；省略环境变量时默认测试本机地址。测试报告保存在忽略提交的 `qa-output/account-http/report.json` 和 `qa-output/account-http-loopback/report.json`。
