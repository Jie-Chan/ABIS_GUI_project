# 2026-11-13 三页底部分页与导出布局

按《20261113-ABIS mock界面开发文档.md》18:37 版更新 §1.8、§1.9、§2.1、§4.1、§6.1。在现有未提交改动上继续开发，未执行 Git commit。

三页采用「筛选栏 → 表格 → 底部操作与分页」布局。筛选栏下直接显示表头，移除原数量说明、范围说明、导出工具条及其空白。查询总数仅在底部分页区显示一次。

- 日志、审计：底部左侧为「导出 CSV」，同排右侧为总数、每页条数和分页。
- 申请人：底部仅保留右对齐的总数和分页。
- 记录在表格内滚动，筛选栏、表头和底部控件保持可见。短列表与空结果使用自然高度及相同底部内边距。
- 624 px 窗口下导出及分页同排显示；更窄窗口允许控件换行，全部保留且无截断，表格高度按实际底部高度调整。
- 查询、排序、分页、返回申请人及 CSV 的已生效条件逻辑继续保留。日志导出提示仍为「导出当前查询的全部日志字段」。

## 修改文件

`src/components/RecordsFooter.vue` 统一底部布局、分页事件及窄屏尺寸；`src/composables/useRecordsTable.js` 按整个底部区域的高度分配表格滚动空间。`ApplicantView.vue`、`LogView.vue`、`AuditView.vue` 接入共用底部并移除表格上方的旧工具条，清除筛选栏后的额外间距。

新增 `frontend-toolkit/verification/review-records-footer.mjs`，并更新受影响的申请人、界面检查及验证命令。

## 实际验证

`npm run build:mock` 通过。本轮执行 8 项底部布局专项、18 项界面检查、12 项查询流程和 12 项申请人回归，共 **50 项检查通过**，无浏览器错误或真实后端请求。

已验证 1422×804、1280×720、624×850、390×844、320×844：

- 三页表头与筛选栏直接相接，左右边界一致，总数仅出现一次。
- 记录滚动 40 px、中段及回顶部时，筛选栏、表头和底部区域坐标一致；表格记录实际移动，横向列线同步。
- 导出、总数、每页条数及分页始终可见；桌面与 624 px 的左右操作同排，更窄窗口无控件遮挡或截断。
- 排序、修改每页条数、翻页、查询、重置后表头位置稳定；零条及少量结果保留自然高度和相同底部内边距。
- 日志按「1：N查重」查询得到 9 条，编辑 U001 后直接导出仍为 9 条，执行查询后列表总数及 CSV 均为 2 条。CSV 保留毫秒并覆盖全部结果页。
- 审计按已生效账号及动作条件导出全部结果，编辑筛选值不改变导出；重置后可导出全部 64 条。
- 窄屏展开、收起「更多筛选」后，底部位置和已生效条件正确，日期面板仍可操作。

在 `frontend-toolkit/verification` 使用 Node 22.23.4 或兼容版本运行专项：

```bash
ABIS_PREVIEW_URL=http://127.0.0.1:5186 npm run test:footer
```

预览启动命令仍为 `npm run dev:mock -- --host 0.0.0.0`，访问 `/applicants`、`/logs`、`/audits`。监控入口 `/monitor`、重采验收入口 `/acceptance/recapture` 继续可用；验收账号和数据范围见 [17:20 版说明](2026-11-13-业务文案与固定表头更新.md)。本轮临时 5187 测试服务在交付前关闭。
