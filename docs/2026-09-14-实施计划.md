# ABIS GUI 管理控制台 前端骨架 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个可运行的 Vue 3 前端骨架，含 6 个页面、按角色控制可见性、数据全部来自可替换的 mock 适配器。

**Architecture:** 纯静态 SPA，无自有后端。页面不直接调用 HTTP，统一经 `src/api/` 中间层；该层有两个可互换的实现（mock / http），由环境变量 `VITE_USE_MOCK` 选择。契约冻结后只改适配器，页面代码不动。

**Tech Stack:** Vue 3（Composition API）、Vite、Element Plus、Vue Router、Pinia、axios。**不使用 TypeScript**（见设计文档 §4.1）。

**Spec:** `docs/2026-09-14-设计方案.md` — 本计划的每一项都从该文档推导，执行时两份对照阅读。

## Global Constraints

以下约束适用于**每一个**任务，不再逐条重复：

- **不使用 TypeScript。** 语言为 JavaScript + JSDoc 注释。
- **界面仅中文**，需求 3.2 要求为后续英文版预留替换能力。文案约束的实际口径是：**同一句文案不得在多个文件里重复，也不得在 JS 逻辑里用字符串拼接生成**。模板中的静态属性文案（如 `<el-table-column label="调用时间" />`、`placeholder="全部"`）**允许直接写在模板里**——将来接入 i18n 时，改写点本来就在模板（换成 `:label="$t('log.calledAt')"`），把它先提到 `<script>` 常量既不影响可翻译性，又会让每个页面多出一堆中转变量。页面级标题、状态映射表、枚举标签这类**会重复使用或需要集中维护**的文案，仍然写在 `<script setup>` 或 `constants/` 中。⚠ **本条的射程是「面向用户的文案」**，因为它的理由是 i18n 可替换性。**文件名（如 `timestampedName` 里拼时间戳）、URL / 存储键、`console` 诊断串不属于文案**，用 `+` 拼是正当的——**不要把它们当成本条的违反来报**。（CSV 表头**不在豁免之列**：用户会读到它，且它同时是契约的一部分。）
- **不实现 HTTPS / TLS**，开发与生产均走 HTTP（需求 3.1）。
- **mock 数据不得包含任何生物图像数据**（base64 人脸 / 指纹）。需求 1.4 danger 框明确禁止，mock 也必须遵守。
- **前端角色控制不构成安全边界。** 需求附录 A.2 要求权限在 ABIS 侧强制校验；前端的可见性控制只是体验优化，代码注释中须写明这一点。
- **阈值取值范围 1–100 的整数**（需求 1.2）。
- **监控刷新周期 1 分钟**（需求 1.3）。
- **不实现**告警外发、图表趋势、服务启停、Top-N 配置、1:1 核验阈值配置。
- **git 提交由人工执行。** 每个任务末尾给出建议提交命令，**执行者不得自行 `git commit`**。

>
> **因此契约冻结、准备交付时必须做两件事（列入《待澄清清单》，见 Task 12）：**
> ① 建 `.env.production` 并显式写 `VITE_USE_MOCK=false`；
> ② 交付前确认产物走的是真实适配器（打开 Network 面板，应看到对 ABIS 管理 API 的真实请求，

- [ ] **Step 3: 建 src/constants/threshold.js**

```js
/**
 * 匹配阈值配置的常量
 * 来源：《ABIS-GUI管理平台需求分析》1.2 匹配阈值配置
 */

/** 阈值取值范围 —— 需求 1.2：1–100 的整数（上限 100 为产品设定值） */
export const THRESHOLD_MIN = 1
export const THRESHOLD_MAX = 100

/**
 * 两类阈值 —— 需求 1.2 配置范围，仅此两项。
 * 不含 Top-N；不含 1:1 核验判定阈值（后者归 SIGATT 业务系统）。
 *
 * protocolLowerBound 为协议生效下限（指纹 40 / 人脸 60），
 * 随接口协议版本变化，不得在界面中长期写死。
 */
export const THRESHOLD_KEYS = [
  { key: 'face',   label: '人脸 1:N 去重相似度阈值', protocolLowerBound: 60 },
  { key: 'finger', label: '指纹 1:N 去重相似度阈值', protocolLowerBound: 40 },
]

/**
 * ★★ 协议生效下限的处置语义 —— 待澄清项，澄清前不得二选一写死 ★★
 *
 * 冲突事实（需求 1.2 已核实）：
 *   · 协议 `$.threshold` 参数表：低于下限「按 40 / 60 默认处理」 → 语义【纠正】
 *   · 协议错误码 4000005：       「传入的阈值不合法」            → 语义【拒绝】
 *   另有一处边界不一致：参数表写指纹「大于 40」，错误码写「≥ 40」。
 *
 * 需求 1.2 的硬性要求：
 *   「澄清前界面不得按任一种语义写死提示文案」
 *   「不得出现界面显示值与实际生效值不一致且无任何提示的情况」
 *
 * 澄清后的动作：只改 ACTIVE_SEMANTICS 一个值，其余代码不动。
 */
export const ACTIVE_SEMANTICS = 'undecided' // 取值：'undecided' | 'coerce' | 'reject'

/** 三套提示文案 —— 全部保留，澄清后由 ACTIVE_SEMANTICS 决定用哪套 */
export const LOWER_BOUND_MESSAGE = {
  // 【未裁决】默认态：不替协议表态，但必须告知存在不确定（需求 1.2 两条约束同时满足）
  undecided: (label, input, bound) =>
    `${label}设置为 ${input}，低于协议生效下限 ${bound}。` +
    `该情形下 ABIS 是按 ${bound} 生效还是拒绝本次设置，协议尚未明确，待澄清后再提交。`,
  // 【纠正】语义：允许提交，但必须明确告知实际生效值
  coerce: (label, input, bound) =>
    `${label}设置为 ${input}，低于协议生效下限 ${bound}；实际生效值为 ${bound}。`,
  // 【拒绝】语义：提交前阻止
  reject: (label, input, bound) =>
    `${label}不得低于协议生效下限 ${bound}，当前值 ${input} 不合法，请修改。`,
}

/** 取当前语义下的提示文案（取值拼错时回退到 undecided，不让调用点抛错） */
export function buildLowerBoundMessage(label, input, bound) {
  const build = LOWER_BOUND_MESSAGE[ACTIVE_SEMANTICS] || LOWER_BOUND_MESSAGE.undecided
  return build(label, input, bound)
}

/**
 * 当前语义是否允许提交低于下限的值。
 *
 * 只有 'coerce' 放行：该语义下 ABIS 会把低值纠正为下限值，提交是有意义的。
 * 'undecided' 与 'reject' 都拦截——语义未明时写入一个效果不可预期的值不是安全选择，
 * 且只有拦截才与 'undecided' 的提示文案「待澄清后再提交」一致。
 */
export function allowsBelowLowerBound(value, bound) {
```

```js
 * 服务状态监控 mock 数据
 * 来源：《ABIS-GUI管理平台需求分析》1.3 服务状态监控
 */
import {
  MONITOR_TARGET,
  MONITOR_TARGETS,
  MONITOR_STATUS,
  LICENSE_STATUS,
} from '@/constants/monitor'
import { formatDateTime } from '@/utils/datetime'

/**
 * 目标级演示状态 —— 六项覆盖**全部四态**，使每个状态在界面上都可见、可验证。
 *
 * ⚠ 为什么不能只造「正常」+「未部署」：
 *   若数据里不存在任何异常项，顶部「全部正常」标签必然是绿的，
 *   无论 isAbnormal 过滤有没有正确排掉「未部署」——这个验证永远不会失败，
 *   因此它证明不了需求 1.3 的核心断言「未部署不触发异常标识」。
 *   只有让 abnormal 与 unreachable 各真实出现一次，异常计数才是一个
 *   可证伪的数字（正确为 2；若 isAbnormal 过滤失效、把 MinIO 的未部署
 *   也算进去，会显示 3）。
 */
const DEMO_STATUS = {
  [MONITOR_TARGET.FACE]: MONITOR_STATUS.ABNORMAL,
  [MONITOR_TARGET.POSTGRESQL]: MONITOR_STATUS.UNREACHABLE,
  [MONITOR_TARGET.MINIO]: MONITOR_STATUS.NOT_DEPLOYED,   // 按需部署 → 未部署，不是不可达
}

/**
 * 各监控对象的实例状态 —— 按 MONITOR_TARGETS 的 instanceCount 展开。
 *
 * MinIO 为按需部署，此处**刻意造一个「未部署」样本**：
 * 需求 1.3 要求界面能区分「未部署」与「不可达」，且未部署不得触发异常标识。
 */
function buildInstances(target) {
  // MinIO：未部署 → 无实例
  if (target.optional) {
    return []
  }

  const status = DEMO_STATUS[target.key] || MONITOR_STATUS.NORMAL

  return Array.from({ length: target.instanceCount }, (_, i) => ({
    id: `${target.key}-${i + 1}`,
    // 目标级异常/不可达时，首个实例同为该状态，避免行状态与展开明细自相矛盾
    status: status !== MONITOR_STATUS.NORMAL && i === 0 ? status : MONITOR_STATUS.NORMAL,
  }))
}

/** 算法服务的运行指标 —— 需求 1.3，四项 */
function buildMetrics(target) {
  if (!target.algorithm) return undefined
  return {
    cdcHealthy: true,
    cdcReady: true,
    galleryTotalSize: 2000000,
    licenseStatus: LICENSE_STATUS.VALID,
  }
}

/** 生成一次监控快照 */
export function buildMonitorSnapshot() {
  const items = MONITOR_TARGETS.map((target) => ({
    key: target.key,
    name: target.name,
    layer: target.layer,
    optional: target.optional,
    instances: buildInstances(target),
    // 状态取自 DEMO_STATUS（六项覆盖四态）；未列出的默认为「正常」
    status: DEMO_STATUS[target.key] || MONITOR_STATUS.NORMAL,
    metrics: buildMetrics(target),
  }))

  return {
    items,
    fetchedAt: formatDateTime(new Date()),
  }
}
```

```js
/**
 * 日志过滤维度（需求 1.4 五个：时间范围、接口、生物模态、结果状态、耗时区间）
 *
 * ⚠ startTime / endTime 与 r.calledAt 之间是**字符串比较**，三者同为
 *   'YYYY-MM-DD HH:mm:ss' 才成立。传 Date 对象或 'YYYY-MM-DD' 不报错，
 *   只会静默过滤掉全部记录 —— 调用方须先用 formatDateTime 归一化。
 */
function filterLogs(list, { startTime, endTime, api, feature, result, minCost, maxCost } = {}) {
  return list.filter((r) => {
    if (startTime && r.calledAt < startTime) return false
    if (endTime && r.calledAt > endTime) return false
    if (api && r.api !== api) return false
    if (feature && r.feature !== feature) return false
    if (result && r.result !== result) return false
    if (minCost != null && r.costMs < minCost) return false
    if (maxCost != null && r.costMs > maxCost) return false
    return true
  })
}

/**
 * 审计过滤维度
 *
 * ⚠ 同 filterLogs：时间维度按 'YYYY-MM-DD HH:mm:ss' 字符串比较，格式不符会静默过滤为空。
 */
function filterAudits(list, { startTime, endTime, operator, action, result } = {}) {
  return list.filter((r) => {
    if (startTime && r.operatedAt < startTime) return false
    if (endTime && r.operatedAt > endTime) return false
    if (operator && r.operator !== operator) return false
    if (action && r.action !== action) return false
    if (result && r.result !== result) return false
    return true
  })
}

/**
 * 生成 CSV Blob（带 BOM，避免 Excel 打开中文乱码）
 *
 * columns 每项为 [字段名, 表头文案, key→label 快查表?]。
 * 第三项可选：给出时把枚举 key 转成中文（'face' → '人脸'），未命中或未给出则原样输出。
 */
function toCsvBlob(rows, columns) {
  const header = columns.map(([, label]) => label).join(',')
  const body = rows
    .map((row) => columns
      .map(([key, , labelMap]) => {
        const raw = row[key] ?? ''
        const text = (labelMap && labelMap[raw]) || raw
        return `"${String(text).replace(/"/g, '""')}"`
      })
      .join(','))
    .join('\n')
  return new Blob([`﻿${header}\n${body}`], { type: 'text/csv;charset=utf-8' })
}
```

```js
/**
 * 登录态与当前账户角色
 * 需求 1.1：本地账户 + 密码认证；会话应有空闲超时。
 */
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import api from '@/api'
import { hasPermission as checkPermission } from '@/constants/roles'

const TOKEN_KEY = 'abis_console_token'

export const useAuthStore = defineStore('auth', () => {
  const account = ref(null)
  const token = ref(localStorage.getItem(TOKEN_KEY) || '')

  const isLoggedIn = computed(() => !!account.value)
  const role = computed(() => account.value?.role || '')

  /** 判断当前账户是否具备某权限（仅用于界面可见性，非安全边界） */
  function hasPermission(permission) {
    return checkPermission(role.value, permission)
  }

  async function login(username, password) {
    const result = await api.login(username, password)
    account.value = result.account
    token.value = result.token
    localStorage.setItem(TOKEN_KEY, result.token)
    return result
  }

  async function logout() {
    try {
      await api.logout()
    } finally {
      account.value = null
      token.value = ''
      localStorage.removeItem(TOKEN_KEY)
    }
  }

  return { account, token, isLoggedIn, role, login, logout, hasPermission }
})
```

> **骨架简化说明（两条，勿合并）**：
> 1. **会话超时**（需求 1.1）：未实现计时器。真实实现需要 ABIS 侧提供会话有效期——该值尚未冻结，见设计方案 §11 第 12 项。
> 2. **会话恢复**：`account` 不持久化，仅 `token` 从 localStorage 恢复，而 `isLoggedIn` 判定的是 `account`。因此**刷新页面即需重新登录**。契约里 `api.getSession()` 就是预留的恢复路径，骨架中未接线。这不是第 1 条的推论——两者根因不同，必须分别记录（浏览器实测：刷新后访问受限路由会落到登录页，而非停在原页）。

```js
/**
 * 路由与角色守卫
 *
 * ⚠ 守卫仅用于前端体验（隐藏无权限入口），**不构成安全边界**。
 *   需求附录 A.2 要求权限在 ABIS 侧强制校验。
 */
import { createRouter, createWebHistory } from 'vue-router'
import { PERMISSION } from '@/constants/roles'
import { useAuthStore } from '@/stores/auth'

const routes = [
  {
    path: '/login',
    name: 'login',
    component: () => import('@/views/LoginView.vue'),
    meta: { public: true, title: '登录' },
  },
  {
    path: '/',
    component: () => import('@/layouts/AdminLayout.vue'),
    redirect: '/monitor',
    children: [
      {
        path: 'monitor',
        name: 'monitor',
        component: () => import('@/views/MonitorView.vue'),
        meta: { title: '服务状态监控', permission: PERMISSION.MONITOR_VIEW },
      },
      {
        path: 'threshold',
        name: 'threshold',
        component: () => import('@/views/ThresholdView.vue'),
        meta: { title: '匹配阈值配置', permission: PERMISSION.THRESHOLD_EDIT },
      },
      {
        path: 'accounts',
        name: 'accounts',
        component: () => import('@/views/AccountView.vue'),
        meta: { title: '账户管理', permission: PERMISSION.ACCOUNT_MANAGE },
      },
      {
        path: 'logs',
        name: 'logs',
        component: () => import('@/views/LogView.vue'),
        meta: { title: '日志查询', permission: PERMISSION.LOG_VIEW },
      },
      {
        path: 'audits',
        name: 'audits',
        component: () => import('@/views/AuditView.vue'),
        meta: { title: '审计查询', permission: PERMISSION.AUDIT_VIEW },
      },
    ],
  },
  { path: '/:pathMatch(.*)*', redirect: '/monitor' },
]

const router = createRouter({
  history: createWebHistory(),
  routes,
})

router.beforeEach((to) => {
  const auth = useAuthStore()

  if (to.meta.public) {
    return true
  }

  if (!auth.isLoggedIn) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }

  // 无权限时退回监控页（所有角色都有该权限）
  if (to.meta.permission && !auth.hasPermission(to.meta.permission)) {
    return { name: 'monitor' }
  }

  return true
})

export default router
```

```js
/**
 * 监控状态与轮询
 * 需求 1.3：界面按固定周期刷新，初版周期 1 分钟。
 */
import { defineStore } from 'pinia'
import { ref } from 'vue'
import api from '@/api'
import { MONITOR_REFRESH_INTERVAL_MS } from '@/constants/monitor'

export const useMonitorStore = defineStore('monitor', () => {
  const items = ref([])
  const fetchedAt = ref('')
  const loading = ref(false)
  const error = ref('')

  let timer = null

  async function refresh() {
    loading.value = true
    error.value = ''
    try {
      const result = await api.getHealth()
      items.value = result.items
      fetchedAt.value = result.fetchedAt
    } catch (e) {
      error.value = e.message || '获取监控状态失败'
    } finally {
      loading.value = false
    }
  }

  /** 启动轮询（1 分钟）。组件卸载时务必调用 stop() */
  function start() {
    refresh()
    stop()
    timer = setInterval(refresh, MONITOR_REFRESH_INTERVAL_MS)
  }

  function stop() {
    if (timer) {
      clearInterval(timer)
      timer = null
    }
  }

  return { items, fetchedAt, loading, error, refresh, start, stop }
})
```

```vue
<script setup>
import { ref, onMounted, computed } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import api from '@/api'
import {
  THRESHOLD_MIN,
  THRESHOLD_MAX,
  THRESHOLD_KEYS,
  buildLowerBoundMessage,
  allowsBelowLowerBound,
  lowerBoundAlertType,
} from '@/constants/threshold'

const title = '匹配阈值配置'
const loading = ref(false)
const saving = ref(false)
const error = ref('')

/**
 * 初始值刻意留 `null` 而不是 0 —— `onMounted(load)` 在**首次渲染之后**才跑，
 * 若初始值是 0，第一帧会把 face=0 / finger=0 判成「低于下限」（0 < 60、0 < 40），
 * 于是加载完成前先闪出两条红色提示条再消失，像是一次假告警。
 * `null` 表示「尚未拿到值」，此时不产生任何提示。
 */
const form = ref({ face: null, finger: null })
const origin = ref({ face: null, finger: null })

/**
 * 低于协议生效下限的提示。
 * 需求 1.2：澄清前不得按任一种语义写死；澄清后由 ACTIVE_SEMANTICS 决定。
 */
const lowerBoundHints = computed(() =>
  THRESHOLD_KEYS
    .filter((k) => form.value[k.key] !== null && form.value[k.key] < k.protocolLowerBound)
    .map((k) => ({
      key: k.key,
      text: buildLowerBoundMessage(k.label, form.value[k.key], k.protocolLowerBound),
    }))
)

/** 校验：1–100 的整数（需求 1.2）；拒绝语义下另加下限校验 */
function validate() {
  for (const k of THRESHOLD_KEYS) {
    const v = form.value[k.key]
    if (!Number.isInteger(v) || v < THRESHOLD_MIN || v > THRESHOLD_MAX) {
      ElMessage.error(`${k.label}须为 ${THRESHOLD_MIN}–${THRESHOLD_MAX} 的整数`)
      return false
    }
    if (!allowsBelowLowerBound(v, k.protocolLowerBound)) {
      ElMessage.error(buildLowerBoundMessage(k.label, v, k.protocolLowerBound))
      return false
    }
  }
  return true
}

async function load() {
  loading.value = true
  error.value = ''
  try {
    const result = await api.getThresholds()
    form.value = { ...result }
    origin.value = { ...result }
  } catch (e) {
    // 不接住这个异常，加载失败的三重后果都不可见：界面没有任何提示、
    // 控制台留下一条未处理的 rejection、而 form 停在初始值上 ——
    // 用户看到的是一张空白表单，而不是「读取失败」。
    // 与 Task 6 的 store.refresh() 保持同一形态：catch 住，落到 error，由视图呈现。
    error.value = e.message || '读取阈值配置失败'
  } finally {
    loading.value = false
  }
}

async function handleSave() {
  if (!validate()) return

  // 需求 1.2：阈值修改应经二次确认
  try {
    await ElMessageBox.confirm(
      `确认将人脸阈值由 ${origin.value.face} 改为 ${form.value.face}，` +
      `指纹阈值由 ${origin.value.finger} 改为 ${form.value.finger}？`,
      '二次确认',
      { type: 'warning' }
    )
  } catch {
    // 用户点「取消」时 ElMessageBox.confirm 会 **reject 一个 'cancel'**。
    // 不接住它，本函数作为 @click 处理器被 Vue 的异步错误通道调用，
    // 于是**每次取消都在控制台留下一条报错**（开发构建下另有 unhandled rejection）。
    // 功能没坏，但「取消」是常规操作，不该产生错误 —— 直接 return 即可。
    // ⚠ 这个 `return` 是**功能性的**，不是洁癖：删掉它，执行会继续落到下面的
    //   saving.value = true 与 api.updateThresholds()，**点「取消」会真的把阈值保存下去**。
    //   （`saving` 由 `finally` 复位，所以并不会出现「按钮一直转圈」。）
    return
  }

  saving.value = true
  try {
    const result = await api.updateThresholds({ ...form.value })
    form.value = { ...result }
    origin.value = { ...result }
    // 需求 1.2：界面应提示变更的生效延迟
    ElMessage.success('阈值已保存。变更将在各实例下次轮询后生效，最长约 1 分钟。')
  } catch (e) {
    ElMessage.error(e.message || '保存失败')
  } finally {
    saving.value = false
  }
}

onMounted(load)
</script>

<template>
  <div>
    <el-card v-loading="loading">
      <template #header>
        <span>{{ title }}</span>
      </template>

      <el-alert
```

```js
/** 触发浏览器下载一个 Blob */
export function downloadBlob(blob, filename) {
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = filename
  document.body.appendChild(link)
  link.click()
  document.body.removeChild(link)
  URL.revokeObjectURL(url)
}

/** 生成带时间戳的文件名 */
export function timestampedName(prefix, ext = 'csv') {
  const d = new Date()
  const pad = (n) => String(n).padStart(2, '0')
  const stamp =
    `${d.getFullYear()}${pad(d.getMonth() + 1)}${pad(d.getDate())}` +
    `_${pad(d.getHours())}${pad(d.getMinutes())}${pad(d.getSeconds())}`
  return `${prefix}_${stamp}.${ext}`
}
```
