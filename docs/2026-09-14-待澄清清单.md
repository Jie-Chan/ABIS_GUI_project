# ABIS GUI 管理控制台 — 待澄清清单

本文档列出管理控制台前端建设过程中识别出的、需求文档未回答或自相矛盾的事项。

**用途**：作为抛给 ABIS 侧与部署侧的确认底稿，逐项确认或修改后即为联调依据。

**背景**：管理控制台是纯 API 消费者，其全部数据来自 ABIS 侧管理 API。
《ABIS-GUI管理平台需求分析》附录 A.1 所列为 8 条管理 API，目前**均未冻结**，
且全部需 ABIS 侧新建。本清单中的第 1 项是其余各项的总闸口。

**本文档分三段，性质不同，请勿合并阅读：**
1. 需求歧义主列表（**需要 ABIS 侧回答**）；
2. 附：GUI 侧自查发现（**非需求歧义**，我们自己侧的配置/实现问题，供留档与拍板）；
3. 附：验收过程中新增的待澄清项（**同样需要 ABIS 侧回答**，只是不在原定 15 项之内）。

## 第 2 段：附 —— GUI 侧自查发现（非需求歧义）

**⚠ 本段分两档，严重程度不同，不得平铺阅读。** 收尾阶段在盘上实测过，条目沿用收尾记录编号 A1–A10。

### A1–A3：需要拍板的配置 / 实现问题

#### A1. `dist/` 里编译进了演示口令 —— 交付风险，非提交风险

- **事实**：仓库根目录存在一份构建产物 `dist/`，`admin123` 明文出现在 `dist/assets/` 下的
  两个 JS chunk 里（`grep -rl "admin123" dist/assets/` 可复现）。
  ⚠ 这两个文件名含**构建内容哈希，每次 `vite build` 都会变**，故此处不钉死文件名，
  以该 grep 实测为准。
  这正是 README「⚠ 生产构建（部署前必读）」一节警告**不得部署**的那个产物
  （`vite build` 走 `mode=production`，不加载 `.env.development` ⇒ `VITE_USE_MOCK` 为
  `undefined` ⇒ 静默使用 mock 适配器，演示账号被编译进去）。
- **风险等级**：**不会进 commit** —— `dist/` 在 `.gitignore` 里（`git check-ignore -q dist/a`
  输出 `IGNORED`）。风险在**交付 / 打包**环节：谁若把整个工程目录压缩或上传，
  就把一份带演示口令、且连不上真 API 的构建一起带走了。
- **建议**：交付前删除 `dist/`（`npm run build` 可随时重建，无信息损失）。
  **是否删除由 JayChen 决定** —— 它是构建产物，不属于实现者。**本任务未触碰 `dist/`。**
- **归属**：部署侧 / JayChen。

#### A2. favicon 的 `404`（**已在 Task 12 Step 0 修掉**，此处如实记录）

- **原实测**：`index.html` 的 head 只有 charset / viewport / title 三行，没有
  `<link rel="icon">`；且不存在 `public/` 目录。⇒ 浏览器按默认规则请求
  `/favicon.ico` → 404，**每次整页加载必有**。
- **处置**：在 `index.html` head 补一行 `<link rel="icon" href="data:image/svg+xml,...">`，
  中性几何标记。**未新增 `public/favicon.ico` 二进制，未伪造任何机构标识。**
- **修复后实测**：控制台 `errors` 计数 **0**；Network 全量请求列表中**不再出现
  `/favicon.ico`**（全部请求均为 200）。
- **遗留**：无。此项**已闭合**，列出仅为留档。

#### A3. 生产构建默认静默走 mock，且这份责任目前无人认领

- **事实**：`VITE_USE_MOCK !== 'false'` 即使用 mock。生产构建不加载 `.env.development`，
  因此**默认就是 mock**。要交付真环境，必须创建 `.env.production` 并写 `VITE_USE_MOCK=false`。
- **实测**：`git check-ignore -q .env.production` → `TRACKABLE`，即该文件**可以**被提交
  （不是被忽略掉的文件），所以这不是「文件找不到」的问题，是**没有人负责创建它**。
- **风险**：默认方向是**不安全**的（`undefined` 走 mock 而非报错）。
  若部署者不知道这条，会得到一个「能打开、登录得进去、但数据和真 ABIS 毫无关系」的控制台
  —— **而且没有任何报错提示它是假的**。
- **建议**：二选一 ——（a）把默认反转：只有显式 `VITE_USE_MOCK === 'true'` 才用 mock，
  未配置时走 http 适配器并抛出明确错误（与完成标准第 7 条「抛出明确错误而非静默失败」同向）；
  （b）保持现状但在 `.env.example` / README 里把责任明确指派给部署侧。
  **倾向 (a)** —— 默认值应当指向安全的一侧。
- **归属**：需要拍板：GUI 侧改默认值，还是部署侧认领 `.env.production`。

### A4–A10：潜伏的代码层观察

**⚠ 本档各条均已实测定位，但当前不触发。** 下列每条**照抄收尾记录里的「可达性」与「等级」判定**，
未做抬升，也未写成「会崩」——断言必须对应实测，这是本项目的一贯规矩。

#### A4. `toCsvBlob` 表头行不加引号，正文却加 —— 不对称

- **位置**：`src/api/adapters/mock.js:221` 的私有 helper，`exportLogs` / `exportAudits` 调用它。
- **事实**：正文单元格做了引号包裹 + `"` → `""` 转义，表头**两样都没有**。
- **可达性**：当前表头文案全是中文且不含逗号 / 引号，**所以现在是潜伏的**；
  将来出现一个含 `,` 或 `"` 的表头文案（如 `时间,精确到秒`）会**静默错列**。
- **等级**：Minor，潜伏。

#### A5. `Object.keys(payload)` 会抛出**英文** TypeError —— 真实但**从本 UI 不可达**

- **位置**：`src/api/adapters/mock.js:123`。
- **可达性判定**：唯一调用方是 `ThresholdView.vue`，且**恒传对象**
  （`api.updateThresholds({ ...form.value })`）⇒ **在当前 UI 下不可达**。
- **等级**：**降级为契约层健壮性备注，不作为缺陷。** 若写进交付文档，应表述为
  「API 层未防御缺参调用」（给 ABIS 侧看契约时值得提一句），**不要写成「会崩」**。

#### A6. `labelMap[raw]` 未做原型链防护

- **位置**：`src/api/adapters/mock.js:227`。`labelMap &&` 只挡了 `labelMap` 为空，
  **没挡原型链**。若 `raw === 'constructor'` / `'toString'`，查表命中 `Object.prototype`
  上的函数（**真值**），`text` 变成函数对象，`String(text)` 会把**函数源码**写进 CSV。
- **可达性**：`raw` 来自记录字段值。当前 mock 数据的枚举值都是正常 key ⇒ **现在不触发**；
  真实 ABIS 若返回意外字符串则触发。
- **等级**：Minor，潜伏。**这正是本项目「值恰好相等 ≠ 是同一个东西」家族的一个近亲**
  —— 这里的形态是「查表命中 ≠ 命中了我想要的那一项」。

#### A7. `getSession()` 恒返回 `null`（会话恢复未实现）

- **位置**：`src/api/adapters/mock.js:58–61`，而契约 `src/api/contract.js:116` 声明其签名是
  `() => Promise<{account}|null>` —— **签名允许返回账户，实现恒返回 null**。
- **可达性**：**每次整页加载 / 刷新页面即丢登录态**，稳定复现。
- **等级**：Minor，潜伏（当前无 ABIS 侧会话可恢复，故不阻塞）。
- **⚠ 不要与另一条合并**：实施计划「已知遗留」表里的**「会话空闲超时未实现」是另一件事**
  —— 那条是「ABIS 侧没给会话有效期，所以做不了空闲超时」。**前者是我们自己的 store 没做恢复，
  后者是上游没给参数，归属不同。** 写进交付文档时必须分成两条。

#### A8. `http`（axios 实例）被具名导出但无人消费

- **位置**：`src/api/adapters/http.js:12` 创建、`:64` `export { http }`。
  全仓搜索 `adapters/http` 的导入者只有 `src/api/index.js:8`，**取的是默认导出**。
- **附带确认（有价值，非发现）**：`axios` 确在依赖里（`package.json` `"axios": "^1.20.0"`），
  所以 `http.js` 的导入能解析，**不存在依赖缺失导致的构建失败**。
- **等级**：Minor / 整洁性。它也可能是有意留的逃生口。

#### A9. `notReady` 与 `notReadyExport` 近似重复 —— **但不完全重复**

- **位置**：`src/api/adapters/http.js:27` 与 `:35`。
- **差异（重要，故不能简单判为重复）**：`notReady` 的文案**多一句**
  `请检查 .env 中的 VITE_USE_MOCK。`，`notReadyExport` **没有**。
  `notReadyExport` 用于 `exportLogs` / `exportAudits`（返回文件而非 JSON），
  **这句差异可能是有意的**。
- **等级**：Minor / 整洁性。**应写成「公共抛出逻辑可提取，但两者的文案差异需先确认是否有意」**，
  不要断言为纯复制粘贴。

#### A10. `API_METHODS` 是惰性数据（声明了但无人消费）

- **位置**：`src/api/contract.js:135` 定义、`:144` `export default API_METHODS`。
  **全仓再无其他引用**。
- **性质**：它是**给未来做契约一致性校验用的清单**，目前是声明性数据。
- **等级**：Minor / 说明性。**不宜写成缺陷**，宜写成「契约自检尚未接线」。

## 第 3 段：附 —— 验收过程中新增的待澄清项

本段与第 1 段**同类**（都是需要 ABIS 侧回答的需求歧义），但**不在 §11 预定的 15 项之内**。

### A11. ABIS 是否拒绝「停用自己 / 停用最后一个管理员」？

- **由来**：`AccountView.vue` 的 `toggleEnabled` catch 注释曾写着「需求 1.1 的边界：不允许把自己停用 /
  删除，也不允许停用最后一个管理员」。经在需求文档全库检索 `最后一个管理员` / `停用自己` / `禁用自己` /
  `不允许.*自己` / `自身账户` —— **全部零命中**。需求 1.1 实际只规定 **创建 / 修改 / 禁用 / 删除、
  密码重置、禁用后不可登录、角色权限表、本地加盐哈希、会话空闲超时**。
  **⇒ 那条边界是凭空发明的**，该注释已删除。
- **为什么必须问 ABIS 侧**：需求分析要求「管理 API 角色权限校验须在 ABIS 侧强制」，
  所以答案决定的是**契约**（ABIS 要不要拒绝这两种请求），不是我们的界面。
  **前端角色控制不构成安全边界** —— 界面上的可见性控制只是体验优化。
- **若 ABIS 侧拒绝**：前端只需把拒绝原因原样呈现即可（现有实现已经这么做，见
  `src/views/AccountView.vue` 的 `toggleEnabled` catch 分支）。
- **若 ABIS 侧不拒绝**：这是一条**能把自己锁在系统外、且没有第二个管理员可救**的操作路径，
  需要产品侧显式接受这个后果。
- **归属**：ABIS 侧 / 产品侧。**建议答复期限**：____
