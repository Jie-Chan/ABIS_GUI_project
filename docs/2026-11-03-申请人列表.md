# 申请人列表一级页面

入口：顶部“申请人列表”，路由 `/applicants`，与服务状态监控、日志查询、审计查询同级。管理员和运维员均拥有 `applicant:view` 查看权限，入口不归入设置。

## 展示和交互

- 一行一位当前库内申请人，按业务 `userId` 去重；人员数据独立于控制台账户和调用日志。
- 列表展示申请人 ID、人脸入库情况/数量、指纹入库情况/数量、首次入库时间、最近更新时间。
- 申请人 ID 按字符串精确匹配，保留前导零；可与入库模态和首次入库时间组合查询。
- 模态“有人脸”“有指纹”包含双模态人员，“人脸和指纹”仅保留双模态人员。
- 查询与调整每页条数回到第一页，普通翻页保留筛选；查询失败清空旧结果，与查无匹配区分；旧请求不覆盖新结果。
- 查看详情打开右侧抽屉，显示人员摘要和每条入库记录的模态、记录 ID、更新时间；读取失败支持重新读取，关闭或切换人员时旧请求结果失效。
- 列表和详情均可查看日志，跳转 `/logs?userId=...` 自动带入申请人并查询。日志页已挂载时变更参数同样重新查询，清除上一个人的其他筛选条件。
- 当前提供只读查询，不增加入库、修改或删除操作。

新增一级菜单后调整顶部导航响应式断点：1400px 以下收紧导航，1200px 以下分成两行，窄屏导航内部可横向滚动；内容和账户控件不重叠。

## Mock 和接口边界

`src/mock/applicants.js` 生成 68 位独立在库人员，包含单人脸、单指纹和双模态。首位申请人为 `00000001`，便于与日志 ID 查询联合体验；有的在库人员没有当前 Mock 日志，不能据此判断其未入库。

契约增加：

- `listApplicants({page, pageSize, userId, modality, startTime, endTime})` → `{total, items}`；每项包含 `userId/faceCount/fingerCount/enrolledAt/updatedAt`。
- `getApplicant(userId)` → 人员摘要及 `records[]`；记录包含 `recordId/feature/enrolledAt/updatedAt`。

真实后端需基于当前底库提供去重、聚合、筛选、分页和详情；姓名、证件号及照片没有数据来源，本轮不增加。HTTP 适配器新增明确报未实现的占位方法，不虚构接口路径，也不回退到 Mock 冒充真实入库数据。联调工程未修改。
